Basics

1. Two kinds of types: primitives and wrappers

Primitive: stores the value itself. Fast, never null, has no methods. Written in lower case: int, double, boolean.

Wrapper: a class (an object) that holds a primitive. Can be null, has useful methods, and is required by generics. Written with a capital letter: Integer, Double, Boolean.

String is NOT a primitive; it is a class.

int a = 5;          // primitive: just the number 5
Integer b = 5;      // wrapper: an object holding 5
Integer c = null;   // possible only for a wrapper

2. The eight primitives and their wrappers

  Primitive | Wrapper   | Size   | Default | Notes
  ----------|-----------|--------|---------|---------------------------------
  byte      | Byte      | 8 bit  | 0       | -128 .. 127
  short     | Short     | 16 bit | 0       |
  int       | Integer   | 32 bit | 0       | the default integer type
  long      | Long      | 64 bit | 0L      | literal needs L: 10000000000L
  float     | Float     | 32 bit | 0.0f    | literal needs f: 1.5f
  double    | Double    | 64 bit | 0.0     | the default decimal type
  char      | Character | 16 bit | 0 (nul) | one character in single quotes: 'a'
  boolean   | Boolean   | n/a    | false   | true or false

The default is what a field or an array element gets if you set nothing. For every wrapper the default is null, not 0.

long big = 10000000000L;  // without L: "integer number too large"
float f = 1.5f;           // without f: 1.5 is a double and does not fit into float
char letter = 'a';        // single quotes for char, double quotes for String

3. When to use which

  • Primitive by default: counters, math, flags.
  • Wrapper when you need null ("no value"), or inside generics: Map<String, Long>. Generics cannot hold primitives: Map<String, long> does not compile.
int count = 0;                    // a counter: primitive
Integer maybeAge = null;          // age may be unknown: wrapper

Converting

4. Autoboxing and unboxing

Java converts between a primitive and its wrapper automatically.
  boxing:   int -> Integer
  unboxing: Integer -> int
Integer boxed = 5;       // boxing
int primitive = boxed;   // unboxing

5. Parsing: String to number and back

Integer.parseInt("42") turns text into an int. String.valueOf(42) turns a number into text. Text that is not a number throws NumberFormatException.

int a = Integer.parseInt("42");             // 42
double d = Double.parseDouble("3.14");      // 3.14
String text = String.valueOf(42);           // "42"
Integer boxed = Integer.valueOf(42);        // 42 as an Integer

// Integer.parseInt("abc");   // NumberFormatException: For input string: "abc"
// Integer.parseInt("");      // NumberFormatException

6. Casting: widening and narrowing

Widening (smaller -> bigger type) is automatic and safe: int -> long -> double. Narrowing (bigger -> smaller) needs a cast in brackets and may lose data.

long big = 5;                   // int -> long, automatic
double dbl = 5;                 // int -> double, automatic: 5.0

int truncated = (int) 3.99;     // 3: the decimals are CUT, not rounded
byte overflow = (byte) 200;     // -56: 200 does not fit into byte (max 127)
int rounded = (int) Math.round(3.99); // 4: use Math.round to round

Traps

7. Unboxing null: NullPointerException

A wrapper may be null, a primitive may not. If you unbox a null wrapper, the program crashes.

Integer value = null;
// int x = value;   // NullPointerException

int safe = (value != null) ? value : 0;   // check first -> 0

8. Comparing wrappers: == or equals?

For primitives == compares values. For wrappers == compares REFERENCES (are these the same object?), not values. Always use equals() for wrappers.

Integer caches the values -128 .. 127, so == "works" for small numbers by accident and fails for big ones. Do not rely on it.

int a = 1000, b = 1000;
System.out.println(a == b);             // true: primitives

Integer c = 1000, d = 1000;
System.out.println(c == d);             // false (!) two different objects
System.out.println(c.equals(d));        // true: compares values

Integer e = 100, f = 100;
System.out.println(e == f);             // true, only because 100 is cached

9. Integer division, overflow, double precision

Three classic surprises with numbers.

// Integer division: int / int is an int, the decimals are cut
System.out.println(5 / 2);              // 2, not 2.5
System.out.println(5 / 2.0);            // 2.5: one operand is a double
System.out.println(5 % 2);              // 1: the remainder

// Overflow: int has no room for a bigger number and wraps around
System.out.println(Integer.MAX_VALUE);      // 2147483647
System.out.println(Integer.MAX_VALUE + 1);  // -2147483648 (!)
System.out.println(Integer.MAX_VALUE + 1L); // 2147483648: use long

// Precision: double stores decimals approximately
System.out.println(0.1 + 0.2);              // 0.30000000000000004
System.out.println(0.1 + 0.2 == 0.3);       // false
// For money use BigDecimal or whole cents in a long.

Основы

1. Два вида типов: примитивы и обёртки

Примитив: хранит само значение. Быстрый, никогда не null, методов нет. Пишется с маленькой буквы: int, double, boolean.

Обёртка: класс (объект), который хранит примитив. Может быть null, имеет полезные методы и нужна для generics. Пишется с большой буквы: Integer, Double, Boolean.

String НЕ примитив; это класс.

int a = 5;          // примитив: просто число 5
Integer b = 5;      // обёртка: объект, хранящий 5
Integer c = null;   // возможно только для обёртки

2. Восемь примитивов и их обёртки

  Примитив  | Обёртка   | Размер | По умолч.| Примечания
  ----------|-----------|--------|----------|--------------------------------
  byte      | Byte      | 8 бит  | 0        | -128 .. 127
  short     | Short     | 16 бит | 0        |
  int       | Integer   | 32 бит | 0        | целый тип по умолчанию
  long      | Long      | 64 бит | 0L       | в литерале нужна L: 10000000000L
  float     | Float     | 32 бит | 0.0f     | в литерале нужна f: 1.5f
  double    | Double    | 64 бит | 0.0      | дробный тип по умолчанию
  char      | Character | 16 бит | 0 (nul)  | один символ в одинарных кавычках: 'a'
  boolean   | Boolean   | н/д    | false    | true или false

«По умолчанию» это значение, которое получает поле или элемент массива, если ничего не задать. Для любой обёртки значение по умолчанию null, а не 0.

long big = 10000000000L;  // без L: "integer number too large"
float f = 1.5f;           // без f: 1.5 это double и не помещается в float
char letter = 'a';        // одинарные кавычки для char, двойные для String

3. Что когда использовать

  • По умолчанию примитив: счётчики, математика, флаги.
  • Обёртка, когда нужен null («значения нет») или внутри generics: Map<String, Long>. Generics не могут хранить примитивы: Map<String, long> не компилируется.
int count = 0;                    // счётчик: примитив
Integer maybeAge = null;          // возраст может быть неизвестен: обёртка

Преобразования

4. Автоупаковка и распаковка

Java сама преобразует примитив в обёртку и обратно.
  упаковка (boxing):     int -> Integer
  распаковка (unboxing): Integer -> int
Integer boxed = 5;       // упаковка
int primitive = boxed;   // распаковка

5. Парсинг: строка в число и обратно

Integer.parseInt("42") превращает текст в int. String.valueOf(42) превращает число в текст. Текст, который не является числом, бросает NumberFormatException.

int a = Integer.parseInt("42");             // 42
double d = Double.parseDouble("3.14");      // 3.14
String text = String.valueOf(42);           // "42"
Integer boxed = Integer.valueOf(42);        // 42 как Integer

// Integer.parseInt("abc");   // NumberFormatException: For input string: "abc"
// Integer.parseInt("");      // NumberFormatException

6. Приведение типов: расширение и сужение

Расширение (меньший -> больший тип) автоматическое и безопасное: int -> long -> double. Сужение (больший -> меньший) требует приведения в скобках и может потерять данные.

long big = 5;                   // int -> long, автоматически
double dbl = 5;                 // int -> double, автоматически: 5.0

int truncated = (int) 3.99;     // 3: дробная часть ОТБРАСЫВАЕТСЯ, а не округляется
byte overflow = (byte) 200;     // -56: 200 не помещается в byte (максимум 127)
int rounded = (int) Math.round(3.99); // 4: для округления используйте Math.round

Ловушки

7. Распаковка null: NullPointerException

Обёртка может быть null, примитив нет. Если распаковать null-обёртку, программа упадёт.

Integer value = null;
// int x = value;   // NullPointerException

int safe = (value != null) ? value : 0;   // сначала проверка -> 0

8. Сравнение обёрток: == или equals?

Для примитивов == сравнивает значения. Для обёрток == сравнивает ССЫЛКИ (это один и тот же объект?), а не значения. Для обёрток всегда используйте equals().

Integer кэширует значения -128 .. 127, поэтому == «работает» для маленьких чисел случайно и ломается для больших. Не полагайтесь на это.

int a = 1000, b = 1000;
System.out.println(a == b);             // true: примитивы

Integer c = 1000, d = 1000;
System.out.println(c == d);             // false (!) два разных объекта
System.out.println(c.equals(d));        // true: сравнивает значения

Integer e = 100, f = 100;
System.out.println(e == f);             // true, только потому что 100 в кэше

9. Целочисленное деление, переполнение, точность double

Три классических неожиданности с числами.

// Целочисленное деление: int / int это int, дробная часть отбрасывается
System.out.println(5 / 2);              // 2, а не 2.5
System.out.println(5 / 2.0);            // 2.5: один операнд double
System.out.println(5 % 2);              // 1: остаток

// Переполнение: в int не хватает места для большего числа, и значение «заворачивается»
System.out.println(Integer.MAX_VALUE);      // 2147483647
System.out.println(Integer.MAX_VALUE + 1);  // -2147483648 (!)
System.out.println(Integer.MAX_VALUE + 1L); // 2147483648: используйте long

// Точность: double хранит дроби приблизительно
System.out.println(0.1 + 0.2);              // 0.30000000000000004
System.out.println(0.1 + 0.2 == 0.3);       // false
// Для денег используйте BigDecimal или целое число копеек в long.

Basics

1. Syntax and execution order: for (init; condition; update)

A loop repeats a block of code. Use for when you know in advance how many times to repeat, or when you need a counter.

The header has three parts, all optional, separated by ;

  • init: runs once, usually declares the counter (int i = 0)
  • condition: checked before every iteration; the loop stops when it is false
  • update: runs after every iteration, usually changes the counter (i++)

Order: init -> condition -> body -> update -> condition -> body -> update ... -> condition is false -> exit.

// Print 0 1 2 3 4:
for (int i = 0; i < 5; i++) {
    System.out.println(i);
}

// The counter exists only inside the loop. This does not compile:
// System.out.println(i);

2. Counting up, down and with a step

Change the init, the condition and the update to get any sequence. i++ is the same as i += 1; i-- is the same as i -= 1.

// Up: 1 2 3 4 5
for (int i = 1; i <= 5; i++) {
    System.out.println(i);
}

// Down: 5 4 3 2 1
for (int i = 5; i >= 1; i--) {
    System.out.println(i);
}

// Step 2: 0 2 4 6 8 10
for (int i = 0; i <= 10; i += 2) {
    System.out.println(i);
}

// < excludes the end, <= includes it.
// for (int i = 0; i < 3; i++)  -> 0 1 2   (3 iterations)
// for (int i = 0; i <= 3; i++) -> 0 1 2 3 (4 iterations)

3. Nested loops

A loop inside a loop. The inner loop runs fully for every iteration of the outer one: 3 x 3 iterations = 9 runs of the body.

// Multiplication table 3 x 3:
for (int i = 1; i <= 3; i++) {
    for (int j = 1; j <= 3; j++) {
        System.out.print(i * j + "\t");
    }
    System.out.println(); // new line after each row
}
// 1  2  3
// 2  4  6
// 3  6  9

Controlling a loop

4. break and continue

break leaves the loop completely. continue skips the rest of the current iteration and goes to the update part.

// continue: skip 3 -> 0 1 2 4 5 6 7 8 9
for (int i = 0; i < 10; i++) {
    if (i == 3) continue;
    System.out.println(i);
}

// break: stop at 6 -> 0 1 2 3 4 5
for (int i = 0; i < 10; i++) {
    if (i == 6) break;
    System.out.println(i);
}

// In nested loops break leaves only the INNER loop.

5. Infinite loop

All three header parts are optional. Without a condition the loop never stops by itself: leave it with break or return.

int n = 0;
for (;;) {
    n++;
    if (n > 3) break;
}

// A trap: a condition that is always true by mistake
// for (int i = 0; i >= 0; i++) { ... } // i never becomes negative (until overflow)

Looping over data

6. Array by index

Use an index when you need the position or want to change elements. An array of length n has indexes 0 .. n-1. Length of an array is arr.length (no parentheses).

int[] arr = {10, 20, 30};

// Print every element:
for (int i = 0; i < arr.length; i++) {
    System.out.println(arr[i]);
}

// Double every element (changes the array):
for (int i = 0; i < arr.length; i++) {
    arr[i] = arr[i] * 2; // {20, 40, 60}
}

// A trap: <= instead of <. The array has 3 elements, index 3 does not exist:
// for (int i = 0; i <= arr.length; i++) { arr[i] }
// -> ArrayIndexOutOfBoundsException: Index 3 out of bounds for length 3

7. for-each

for (Type x : collection) takes elements one by one. It is shorter and has no index to get wrong. Use it when you only read the elements.

int[] arr = {10, 20, 30};

for (int x : arr) {
    System.out.println(x);
}

// x is a COPY of the element. Changing x does not change the array:
for (int x : arr) {
    x = x * 2; // arr is still {10, 20, 30}
}

// Need the index or want to change the elements -> use a loop by index (see 6).
// Works the same for List: see ListTheory.

// A trap: a semicolon after the for header is an EMPTY body.
// The block below is not part of the loop and runs once:
//
//   for (int i = 0; i < 5; i++);
//   {
//       System.out.println("hello"); // prints once, not 5 times
//   }

Основы

1. Синтаксис и порядок выполнения: for (init; condition; update)

Цикл повторяет блок кода. Используйте for, когда заранее известно, сколько раз повторять, или когда нужен счётчик.

В заголовке три части, все необязательные, разделены символом ;

  • init: выполняется один раз, обычно объявляет счётчик (int i = 0)
  • condition: проверяется перед каждой итерацией; когда он false, цикл заканчивается
  • update: выполняется после каждой итерации, обычно меняет счётчик (i++)

Порядок: init -> condition -> тело -> update -> condition -> тело -> update ... -> condition false -> выход.

// Вывести 0 1 2 3 4:
for (int i = 0; i < 5; i++) {
    System.out.println(i);
}

// Счётчик существует только внутри цикла. Это не скомпилируется:
// System.out.println(i);

2. Счёт вверх, вниз и с шагом

Меняйте init, condition и update, чтобы получить любую последовательность. i++ то же самое, что i += 1; i-- то же самое, что i -= 1.

// Вверх: 1 2 3 4 5
for (int i = 1; i <= 5; i++) {
    System.out.println(i);
}

// Вниз: 5 4 3 2 1
for (int i = 5; i >= 1; i--) {
    System.out.println(i);
}

// Шаг 2: 0 2 4 6 8 10
for (int i = 0; i <= 10; i += 2) {
    System.out.println(i);
}

// < не включает конец, <= включает.
// for (int i = 0; i < 3; i++)  -> 0 1 2   (3 итерации)
// for (int i = 0; i <= 3; i++) -> 0 1 2 3 (4 итерации)

3. Вложенные циклы

Цикл внутри цикла. Внутренний цикл выполняется полностью на каждую итерацию внешнего: 3 x 3 итерации = 9 запусков тела.

// Таблица умножения 3 x 3:
for (int i = 1; i <= 3; i++) {
    for (int j = 1; j <= 3; j++) {
        System.out.print(i * j + "\t");
    }
    System.out.println(); // перевод строки после каждой строки таблицы
}
// 1  2  3
// 2  4  6
// 3  6  9

Управление циклом

4. break и continue

break полностью выходит из цикла. continue пропускает остаток текущей итерации и переходит к части update.

// continue: пропустить 3 -> 0 1 2 4 5 6 7 8 9
for (int i = 0; i < 10; i++) {
    if (i == 3) continue;
    System.out.println(i);
}

// break: остановиться на 6 -> 0 1 2 3 4 5
for (int i = 0; i < 10; i++) {
    if (i == 6) break;
    System.out.println(i);
}

// Во вложенных циклах break выходит только из ВНУТРЕННЕГО цикла.

5. Бесконечный цикл

Все три части заголовка необязательны. Без условия цикл сам никогда не остановится: выходите из него через break или return.

int n = 0;
for (;;) {
    n++;
    if (n > 3) break;
}

// Ловушка: условие, которое по ошибке всегда истинно
// for (int i = 0; i >= 0; i++) { ... } // i никогда не станет отрицательным (до переполнения)

Обход данных

6. Массив по индексу

Используйте индекс, когда нужна позиция или нужно менять элементы. У массива длины n индексы 0 .. n-1. Длина массива это arr.length (без скобок).

int[] arr = {10, 20, 30};

// Вывести каждый элемент:
for (int i = 0; i < arr.length; i++) {
    System.out.println(arr[i]);
}

// Удвоить каждый элемент (меняет массив):
for (int i = 0; i < arr.length; i++) {
    arr[i] = arr[i] * 2; // {20, 40, 60}
}

Basics

1. Syntax: while (condition)

while repeats the body as long as the condition is true. The condition is checked BEFORE every iteration, so the body may never run: if the condition is false from the start, nothing happens.

Order: condition -> body -> condition -> body ... -> condition is false -> exit.

The counter lives outside the loop and YOU change it in the body. If nothing in the body affects the condition, the loop never ends.

// Print 0 1 2 3 4:
int i = 0;
while (i < 5) {
    System.out.println(i);
    i++; // without this line: infinite loop
}

// The condition is false from the start -> the body never runs:
int x = 10;
while (x < 5) {
    System.out.println(x); // not executed
}

2. while or for?

for: the number of repetitions is known, or you need a counter. while: the number of repetitions is not known in advance; you repeat until something happens.

// Known: exactly 5 times -> for
for (int i = 0; i < 5; i++) {
    System.out.println(i);
}

// Unknown: how many digits are in the number? It takes as many steps as it takes.
int number = 12345;
int digits = 0;
while (number > 0) {
    number /= 10; // drop the last digit: 1234, 123, 12, 1, 0
    digits++;
}
System.out.println(digits); // 5

3. Run at least once: do-while

In do-while the condition is checked AFTER the body, so the body runs at least once. Note the semicolon after the closing parenthesis.

int x = 10;

// x < 5 is false, but the body still runs once -> prints 10:
do {
    System.out.println(x);
} while (x < 5);

// The same condition with plain while prints nothing:
while (x < 5) {
    System.out.println(x);
}

Controlling a loop

4. break and continue

break leaves the loop completely. continue jumps straight to the next condition check.

// break: stop at 6 -> 1 2 3 4 5
int i = 0;
while (i < 10) {
    i++;
    if (i == 6) break;
    System.out.println(i);
}

// A trap: continue BEFORE the update. i never changes, the loop never ends:
// int j = 0;
// while (j < 10) {
//     if (j == 3) continue; // j stays 3 forever
//     j++;
// }
// Update the counter before continue.

5. Infinite loop

while (true) is a normal way to say "repeat until I say stop". Leave it with break or return.

int n = 0;
while (true) {
    n++;
    if (n > 3) break;
}

// A trap: a semicolon after while is an EMPTY body. The loop spins forever:
// int i = 0;
// while (i < 5); { i++; }

Основы

1. Синтаксис: while (condition)

while повторяет тело, пока условие истинно. Условие проверяется ПЕРЕД каждой итерацией, поэтому тело может не выполниться ни разу: если условие ложно с самого начала, ничего не происходит.

Порядок: условие -> тело -> условие -> тело ... -> условие false -> выход.

Счётчик живёт снаружи цикла, и менять его в теле нужно ВАМ. Если ничего в теле не влияет на условие, цикл никогда не закончится.

// Вывести 0 1 2 3 4:
int i = 0;
while (i < 5) {
    System.out.println(i);
    i++; // без этой строки: бесконечный цикл
}

// Условие ложно с самого начала -> тело не выполняется ни разу:
int x = 10;
while (x < 5) {
    System.out.println(x); // не выполняется
}

2. while или for?

for: число повторений известно или нужен счётчик. while: число повторений заранее неизвестно; повторяете, пока что-то не произойдёт.

// Известно: ровно 5 раз -> for
for (int i = 0; i < 5; i++) {
    System.out.println(i);
}

// Неизвестно: сколько цифр в числе? Столько шагов, сколько понадобится.
int number = 12345;
int digits = 0;
while (number > 0) {
    number /= 10; // отбросить последнюю цифру: 1234, 123, 12, 1, 0
    digits++;
}
System.out.println(digits); // 5

3. Хотя бы один раз: do-while

В do-while условие проверяется ПОСЛЕ тела, поэтому тело выполняется минимум один раз. Обратите внимание на точку с запятой после закрывающей скобки.

int x = 10;

// x < 5 ложно, но тело всё равно выполнится один раз -> напечатает 10:
do {
    System.out.println(x);
} while (x < 5);

// То же условие с обычным while ничего не напечатает:
while (x < 5) {
    System.out.println(x);
}

Управление циклом

4. break и continue

break полностью выходит из цикла. continue сразу переходит к следующей проверке условия.

// break: остановиться на 6 -> 1 2 3 4 5
int i = 0;
while (i < 10) {
    i++;
    if (i == 6) break;
    System.out.println(i);
}

// Ловушка: continue ДО обновления. i не меняется, цикл никогда не закончится:
// int j = 0;
// while (j < 10) {
//     if (j == 3) continue; // j навсегда остаётся 3
//     j++;
// }
// Обновляйте счётчик до continue.

5. Бесконечный цикл

while (true) это нормальный способ сказать «повторяй, пока я не скажу стоп». Выходите из него через break или return.

int n = 0;
while (true) {
    n++;
    if (n > 3) break;
}

// Ловушка: точка с запятой после while это ПУСТОЕ тело. Цикл крутится вечно:
// int i = 0;
// while (i < 5); { i++; }

Basics

1. Syntax: if

if runs a block of code only when the condition is true. The condition must be a boolean expression (true or false). If it is false, the block is skipped.

Always use braces { }, even for one line.

int age = 20;

if (age >= 18) {
    System.out.println("Adult"); // runs
}

if (age < 18) {
    System.out.println("Minor"); // skipped
}

2. if-else: two ways

else runs when the condition is false. Exactly one of the two blocks always runs.

int number = 7;

if (number % 2 == 0) {
    System.out.println("Even");
} else {
    System.out.println("Odd"); // runs
}

3. else if: many ways

A chain of conditions. Java checks them from top to bottom and runs the FIRST block whose condition is true; all the rest are skipped. The last else is optional: it runs when nothing matched.

int score = 85;

if (score >= 90) {
    System.out.println("A");
} else if (score >= 80) {
    System.out.println("B"); // runs, the chain stops here
} else if (score >= 70) {
    System.out.println("C");
} else {
    System.out.println("F");
}

Conditions

4. Comparison and logical operators

Comparison (the result is boolean):
  ==  equal         !=  not equal
  >   greater       >=  greater or equal
  <   less          <=  less or equal
Logical:
  &&  AND: both parts must be true
  ||  OR: at least one part must be true
  !   NOT: turns true into false and back
&& is evaluated before ||. Use brackets when you mix them.
int age = 20;
boolean hasTicket = true;

if (age >= 18 && hasTicket) {
    System.out.println("Come in");
}

if (age < 12 || age > 65) {
    System.out.println("Discount");
}

if (!hasTicket) {
    System.out.println("Buy a ticket");
}

// A range 10..20 needs && and the variable twice. This does NOT compile:
// if (10 <= age <= 20) { ... }
if (age >= 10 && age <= 20) {
    System.out.println("In the range");
}

// Brackets make the order clear:
// true || false && false   -> true  (&& first: false, then true || false)
// (true || false) && false -> false

5. Short-circuit: && and ||

Java stops as soon as the result is known.
  a && b: if a is false, b is NOT evaluated (the result is already false).
  a || b: if a is true, b is NOT evaluated (the result is already true).

It is used on purpose: put the safe check first.

String text = null;

// Safe: text != null is false, so text.length() is never called
if (text != null && text.length() > 3) {
    System.out.println("Long text");
}

// The wrong order crashes with NullPointerException:
// if (text.length() > 3 && text != null) { ... }

// The same idea protects from division by zero:
int a = 10, b = 0;
if (b != 0 && a / b > 2) {
    System.out.println("More than 2");
}

6. Comparing strings: equals, not ==

For objects == compares references (is it the same object?), not the text. Always compare strings with equals().

Put the literal first: "yes".equals(answer) works even if answer is null, answer.equals("yes") throws NullPointerException.

String a = "hi";
String b = new String("hi");

System.out.println(a == b);          // false (!) two different objects
System.out.println(a.equals(b));     // true: compares the text
System.out.println("HI".equalsIgnoreCase(a)); // true: ignores case

String answer = null;
System.out.println("yes".equals(answer)); // false, no exception
// answer.equals("yes");                  // NullPointerException

7. Ternary operator: ?:

A short if-else that returns a value: condition ? valueIfTrue : valueIfFalse. Good for simple choices. For longer logic use if-else; avoid nesting ternaries.

int age = 20;

String status = age >= 18 ? "adult" : "minor";
System.out.println(status); // adult

// The same with if-else:
String status2;
if (age >= 18) {
    status2 = "adult";
} else {
    status2 = "minor";
}

int a = 3, b = 8;
int max = a > b ? a : b;    // 8

Traps

8. Braces, semicolon, = instead of ==, order of conditions

Four classic mistakes.

int x = 5;

// 1. No braces: only the FIRST line belongs to the if
// if (x > 10)
//     System.out.println("big");
//     System.out.println("always printed"); // not part of the if!
// Also, else belongs to the NEAREST if. Braces remove all doubts.

// 2. Semicolon after if: an EMPTY body, the block below always runs
// if (x > 10); {
//     System.out.println("always printed");
// }

// 3. = is assignment, == is comparison
// if (x = 5) { ... }   // does not compile for int: int cannot be converted to boolean
boolean flag = false;
if (flag = true) {      // compiles (!): it ASSIGNS true, so the block always runs
    System.out.println("flag is now true");
}

// 4. Order of conditions in else-if: the first match wins
int score = 95;
if (score > 50) {
    System.out.println("Pass");        // prints, even for 95
} else if (score > 90) {
    System.out.println("Excellent");   // never reached
}
// Check the strictest condition first: score > 90, then score > 50.

Основы

1. Синтаксис: if

if выполняет блок кода только тогда, когда условие истинно. Условие должно быть булевым выражением (true или false). Если оно ложно, блок пропускается.

Всегда ставьте фигурные скобки { }, даже для одной строки.

int age = 20;

if (age >= 18) {
    System.out.println("Adult"); // выполнится
}

if (age < 18) {
    System.out.println("Minor"); // пропущено
}

2. if-else: два пути

else выполняется, когда условие ложно. Всегда выполняется ровно один из двух блоков.

int number = 7;

if (number % 2 == 0) {
    System.out.println("Even");
} else {
    System.out.println("Odd"); // выполнится
}

3. else if: много путей

Цепочка условий. Java проверяет их сверху вниз и выполняет ПЕРВЫЙ блок, условие которого истинно; остальные пропускаются. Последний else необязателен: он выполняется, когда ничего не подошло.

int score = 85;

if (score >= 90) {
    System.out.println("A");
} else if (score >= 80) {
    System.out.println("B"); // выполнится, цепочка на этом заканчивается
} else if (score >= 70) {
    System.out.println("C");
} else {
    System.out.println("F");
}

Условия

4. Операторы сравнения и логические операторы

Сравнение (результат boolean):
  ==  равно            !=  не равно
  >   больше           >=  больше или равно
  <   меньше           <=  меньше или равно
Логические:
  &&  И: обе части должны быть истинны
  ||  ИЛИ: хотя бы одна часть должна быть истинна
  !   НЕ: меняет true на false и обратно
&& вычисляется раньше ||. Когда смешиваете их, ставьте скобки.
int age = 20;
boolean hasTicket = true;

if (age >= 18 && hasTicket) {
    System.out.println("Come in");
}

if (age < 12 || age > 65) {
    System.out.println("Discount");
}

if (!hasTicket) {
    System.out.println("Buy a ticket");
}

// Для диапазона 10..20 нужны && и переменная дважды. Это НЕ скомпилируется:
// if (10 <= age <= 20) { ... }
if (age >= 10 && age <= 20) {
    System.out.println("In the range");
}

// Скобки делают порядок понятным:
// true || false && false   -> true  (сначала &&: false, затем true || false)
// (true || false) && false -> false

5. Короткое замыкание: && и ||

Java останавливается, как только результат известен.
  a && b: если a ложно, b НЕ вычисляется (результат уже false).
  a || b: если a истинно, b НЕ вычисляется (результат уже true).

Это используют намеренно: безопасную проверку ставьте первой.

String text = null;

// Безопасно: text != null ложно, поэтому text.length() не вызывается
if (text != null && text.length() > 3) {
    System.out.println("Long text");
}

// Неправильный порядок падает с NullPointerException:
// if (text.length() > 3 && text != null) { ... }

// Та же идея защищает от деления на ноль:
int a = 10, b = 0;
if (b != 0 && a / b > 2) {
    System.out.println("More than 2");
}

6. Сравнение строк: equals, а не ==

Для объектов == сравнивает ссылки (это тот же объект?), а не текст. Строки всегда сравнивайте через equals().

Ставьте литерал первым: "yes".equals(answer) работает, даже если answer равен null, а answer.equals("yes") бросает NullPointerException.

String a = "hi";
String b = new String("hi");

System.out.println(a == b);          // false (!) два разных объекта
System.out.println(a.equals(b));     // true: сравнивает текст
System.out.println("HI".equalsIgnoreCase(a)); // true: игнорирует регистр

String answer = null;
System.out.println("yes".equals(answer)); // false, без исключения
// answer.equals("yes");                  // NullPointerException

7. Тернарный оператор: ?:

Короткий if-else, который возвращает значение: условие ? значениеЕслиTrue : значениеЕслиFalse. Хорош для простого выбора. Для длинной логики используйте if-else; не вкладывайте тернарные операторы.

int age = 20;

String status = age >= 18 ? "adult" : "minor";
System.out.println(status); // adult

// То же самое через if-else:
String status2;
if (age >= 18) {
    status2 = "adult";
} else {
    status2 = "minor";
}

int a = 3, b = 8;
int max = a > b ? a : b;    // 8

Четыре классические ошибки.

int x = 5;

// 1. Без скобок: к if относится только ПЕРВАЯ строка

//     System.out.println("big");
//     System.out.println("always printed"); // не часть if!
// Кроме того, else относится к БЛИЖАЙШЕМУ if. Скобки убирают все сомнения.

// 2. Точка с запятой после if: ПУСТОЕ тело, блок ниже выполняется всегда
// if (x > 10); {
//     System.out.println("always printed");
// }

// 3. = это присваивание, == это сравнение

}

// 4. Порядок условий в else-if: побеждает первое совпадение
int score = 95;

    System.out.println("Pass");        // напечатается даже для 95

}
// Сначала проверяйте самое строгое условие: score > 90, затем score > 50.

Classic switch

1. Syntax: switch, case, default

switch compares one value with several constants and runs the code of the matching case. default runs when nothing matched (it is optional and can be anywhere, usually last).

int day = 3;

switch (day) {
    case 1:
        System.out.println("Monday");
        break;
    case 2:
        System.out.println("Tuesday");
        break;
    case 3:
        System.out.println("Wednesday"); // this one runs
        break;
    default:
        System.out.println("Another day");
}

// case values must be constants: literals, final variables or enum constants.
// case x: with a normal variable x does not compile.

2. break and fall-through

In the classic switch, after the matching case Java keeps running ALL the next cases until it meets break (or the end of the switch). This is called fall-through. A forgotten break is the most common mistake with switch.

int n = 1;

// Forgot break: prints "one", "two" and "default"
switch (n) {
    case 1:
        System.out.println("one");
    case 2:
        System.out.println("two");
    default:
        System.out.println("default");
}

// Fall-through can be useful on purpose, to group cases:
switch (n) {
    case 1:
    case 2:
    case 3:
        System.out.println("small"); // for 1, 2 and 3
        break;
    default:
        System.out.println("big");
}

3. What you can switch on

Allowed: int, short, byte, char (and their wrappers Integer, Short, Byte, Character), String and enum. NOT allowed: long, float, double, boolean. Use if-else for them.

String is compared with equals(), so it is case-sensitive: "Yes" and "yes" are different. A null in switch throws NullPointerException.

String command = "stop";
switch (command) {
    case "start":
        System.out.println("Starting");
        break;
    case "stop":
        System.out.println("Stopping");
        break;
    default:
        System.out.println("Unknown command");
}

char grade = 'B';
switch (grade) {
    case 'A':
        System.out.println("Excellent");
        break;
    case 'B':
        System.out.println("Good");
        break;
    default:
        System.out.println("Other");
}

// long big = 5L;
// switch (big) { ... } // does not compile

Modern switch (Java 14+)

4. Arrow form: case ->

With -> only the code of the matching case runs. There is no fall-through, so break is not needed. Shorter and safer: prefer it.

int day = 3;

switch (day) {
    case 1 -> System.out.println("Monday");
    case 2 -> System.out.println("Tuesday");
    case 3 -> System.out.println("Wednesday");
    default -> System.out.println("Another day");
}

// You can't mix case: and case -> in one switch.

5. Switch as an expression: returns a value

A switch can produce a value, so you can assign it or return it. Put ; after the closing brace. It must cover all the possible values: end it with default (or list every enum constant), otherwise it does not compile.

int day = 3;

String name = switch (day) {
    case 1 -> "Monday";
    case 2 -> "Tuesday";
    case 3 -> "Wednesday";
    default -> "Another day";
};
System.out.println(name); // Wednesday

// Without default it does not compile: "the switch expression does not cover all possible input values"

6. Several values in one case

In the modern form list the values with commas. It replaces the grouped cases from section 2.

int month = 7;

String season = switch (month) {
    case 12, 1, 2 -> "Winter";
    case 3, 4, 5 -> "Spring";
    case 6, 7, 8 -> "Summer";
    case 9, 10, 11 -> "Autumn";
    default -> "Not a month";
};
System.out.println(season); // Summer

7. Block in a branch: yield

If a branch needs several lines, use a block { } and return the value with yield. yield is for switch expressions, return would leave the whole method.

int score = 85;

String result = switch (score / 10) {
    case 10, 9 -> "A";
    case 8 -> {
        System.out.println("Almost excellent");
        yield "B";
    }
    default -> "C or lower";
};
System.out.println(result); // B

Choosing

8. switch or if-else?

switch: one variable compared with exact values (menu command, day of the week, enum). if-else: ranges and conditions (age >= 18, x > 0 && x < 10), booleans, long and double.

A range in switch is not possible: write if-else for it.

int age = 20;

// Range -> if-else
if (age < 18) {
    System.out.println("Minor");
} else {
    System.out.println("Adult");
}

Классический switch

1. Синтаксис: switch, case, default

switch сравнивает одно значение с несколькими константами и выполняет код подходящего case. default выполняется, когда ничего не подошло (он необязателен и может стоять где угодно, обычно последним).

int day = 3;

switch (day) {

        break;
    case 2:
        System.out.println("Tuesday");
        break;
    case 3:
        System.out.println("Wednesday"); // выполнится это
        break;
    default:
        System.out.println("Another day");
}

// Значения case должны быть константами: литералы, final-переменные или константы enum.
// case x: с обычной переменной x не компилируется.

2. break и «проваливание» (fall-through)

В классическом switch после подходящего case Java продолжает выполнять ВСЕ следующие case, пока не встретит break (или конец switch). Это называется fall-through. Забытый break это самая частая ошибка со switch.

int n = 1;

// Забыли break: напечатает "one", "two" и "default"
switch (n) {
    case 1:
        System.out.println("one");
    case 2:
        System.out.println("two");
    default:
        System.out.println("default");
}

// Fall-through бывает полезен намеренно, чтобы сгруппировать case:
switch (n) {
    case 1:
    case 2:
    case 3:
        System.out.println("small"); // для 1, 2 и 3
        break;
    default:
        System.out.println("big");
}

Можно: int, short, byte, char (и их обёртки Integer, Short, Byte, Character), String и enum. НЕЛЬЗЯ: long, float, double, boolean. Для них используйте if-else.

String сравнивается через equals(), поэтому учитывается регистр: "Yes" и "yes" разные. null в switch бросает NullPointerException.

Современный switch (Java 14+)

4. Стрелочная форма: case ->

С -> выполняется только код подходящего case. Fall-through нет, поэтому break не нужен. Короче и безопаснее: предпочитайте её.

int day = 3;

switch (day) {
    case 1 -> System.out.println("Monday");
    case 2 -> System.out.println("Tuesday");
    case 3 -> System.out.println("Wednesday");
    default -> System.out.println("Another day");
}

// Нельзя смешивать case: и case -> в одном switch.

5. Switch как выражение: возвращает значение

switch может выдавать значение, его можно присвоить или вернуть. После закрывающей скобки ставится ;. Он должен покрывать все возможные значения: закончите его default (или перечислите все константы enum), иначе он не скомпилируется.

int day = 3;

String name = switch (day) {
    case 1 -> "Monday";
    case 2 -> "Tuesday";
    case 3 -> "Wednesday";
    default -> "Another day";
};
System.out.println(name); // Wednesday

// Без default не компилируется: "the switch expression does not cover all possible input values"

6. Несколько значений в одном case

В современной форме значения перечисляют через запятую. Это заменяет сгруппированные case из раздела 2.

int month = 7;

String season = switch (month) {
    case 12, 1, 2 -> "Winter";
    case 3, 4, 5 -> "Spring";
    case 6, 7, 8 -> "Summer";
    case 9, 10, 11 -> "Autumn";
    default -> "Not a month";
};
System.out.println(season); // Summer

7. Блок в ветке: yield

Если ветке нужно несколько строк, используйте блок { } и возвращайте значение через yield. yield нужен в выражениях switch, а return выйдет из всего метода.

int score = 85;

String result = switch (score / 10) {
    case 10, 9 -> "A";
    case 8 -> {
        System.out.println("Almost excellent");
        yield "B";
    }
    default -> "C or lower";
};
System.out.println(result); // B

Basics

1. What an array is

An array is a row of numbered cells. All cells hold the same type: only ints, or only Strings, and so on.

Think of an egg carton: it has a fixed number of slots, every slot holds one egg, and the slots are numbered. The numbers start from 0, not from 1. Once the carton is made, you can't add a slot: the size never changes.

// int[] numbers: a row of 3 cells
//
//   value:  [10] [20] [30]
//   index:    0    1    2
//
// The first cell has index 0, the last one has index 2 (size minus 1).

2. Creating an array: with values or empty

Two ways, depending on what you know:

  • You know the values: write them in braces { }. The size is counted for you.
  • You know only the size: new Type[size]. You get that many empty cells.

The type is written with square brackets: int[] is "array of int", String[] is "array of String".

// 1. I know the values
int[] numbers = {10, 20, 30};              // 3 cells: 10, 20, 30
String[] names = {"Anna", "Bob"};          // 2 cells: Anna, Bob

// 2. I know only the size: 5 empty cells (for int they are filled with 0)
int[] empty = new int[5];                  // [0, 0, 0, 0, 0]
String[] places = new String[3];           // [null, null, null]

// The size goes into [] after new. It can be a variable:
int size = 4;
double[] prices = new double[size];        // [0.0, 0.0, 0.0, 0.0]

3. Default values

A new array is never "really empty": every cell already holds a default value.
  int, long, short, byte  -> 0
  double, float           -> 0.0
  boolean                 -> false
  char                    -> the character with code 0 (invisible)
  String and any object   -> null (means "nothing here yet")

A trap: a String cell holds null, and calling a method on null crashes the program.

boolean[] flags = new boolean[2];          // [false, false]
String[] names = new String[2];            // [null, null]

names[0] = "Anna";                         // [Anna, null]
// names[1].length();                      // NullPointerException: cell 1 is still null

Working with elements

4. Read and change an element

Square brackets with an index: array[index]. On the left side of = it writes a value, anywhere else it reads one. The size of an array is array.length (no parentheses, unlike list.size()). The last element is array[array.length - 1].

int[] numbers = {10, 20, 30};

int first = numbers[0];                    // 10: read
numbers[1] = 99;                           // write: {10, 99, 30}
numbers[2] = numbers[2] + 1;               // read, add 1, write back: {10, 99, 31}

int size = numbers.length;                 // 3
int last = numbers[numbers.length - 1];    // 31

5. Adding an element: arrays can't grow

You can't add a cell to an array: the egg carton has a fixed number of slots. numbers[3] = 40 on an array of 3 cells crashes.

To "add" you make a NEW bigger array and copy the old values into it. Arrays.copyOf(old, newSize) does both steps at once: it makes a bigger array and copies the values. The new cells are empty (0 for int). Then you write the new value into the free cell.

If you add often, use a List instead: it grows by itself (see ListTheory).

int[] numbers = {10, 20, 30};

// Step 1: a copy with one more cell
numbers = Arrays.copyOf(numbers, numbers.length + 1);   // {10, 20, 30, 0}

// Step 2: write the new value into the free last cell
numbers[numbers.length - 1] = 40;                       // {10, 20, 30, 40}

// The same with a List, no copying:
List<Integer> list = new ArrayList<>(List.of(10, 20, 30));
list.add(40);                                           // [10, 20, 30, 40]

6. Printing an array

System.out.println(array) does NOT print the values: it prints the type and an address, something like [I@1b6d3586. Arrays.toString(array) prints the values: [10, 20, 30].

int[] numbers = {10, 20, 30};

System.out.println(numbers);                    // [I@1b6d3586 (junk)
System.out.println(Arrays.toString(numbers));   // [10, 20, 30]

7. Looping over an array

To do something with every cell, use a loop (see ForTheory).

  • for by index: when you need the position or want to change the cells.
  • for-each: when you only read the values.
int[] numbers = {10, 20, 30};

// By index: print the position and the value
for (int i = 0; i < numbers.length; i++) {
    System.out.println(i + ": " + numbers[i]);  // 0: 10, 1: 20, 2: 30
}

// for-each: only the values
int sum = 0;
for (int number : numbers) {
    sum += number;
}
System.out.println(sum);                        // 60

Traps

8. ArrayIndexOutOfBoundsException, copying and comparing

Three classic surprises.

1) Index out of range. An array of size n has indexes 0 .. n-1. Anything else
   crashes with ArrayIndexOutOfBoundsException.
2) int[] b = a does NOT copy. It gives the same array a second name: a and b are
   two names of one egg carton, so changing b changes a.
   A real copy: Arrays.copyOf(a, a.length).
3) a == b compares whether it is the same array, not the values.
   To compare the values use Arrays.equals(a, b).
int[] a = {1, 2, 3};

// 1) a[3] -> ArrayIndexOutOfBoundsException: Index 3 out of bounds for length 3

// 2) Second name, not a copy
int[] b = a;
b[0] = 100;                                    // a is {100, 2, 3} too!

int[] copy = Arrays.copyOf(a, a.length);       // a real copy
copy[0] = 5;                                   // a does not change

// 3) Comparing
int[] x = {1, 2};
int[] y = {1, 2};
System.out.println(x == y);                    // false: two different arrays
System.out.println(Arrays.equals(x, y));       // true: same values

Array or List?

9. Array or List? Converting between them

Array: fixed size, can hold primitives (int[]), simple. List: grows and shrinks, has many ready methods (add, remove, contains...), holds objects (List<Integer>).

Not sure? Take a List. Take an array when the size is fixed and known in advance.

Converting:

  • array of objects -> List: new ArrayList<>(Arrays.asList(array))
  • List -> array of objects: list.toArray(new String[0]) Arrays.asList works for String[] and Integer[], but not for int[].
String[] array = {"a", "b", "c"};

List<String> list = new ArrayList<>(Arrays.asList(array));  // [a, b, c]
list.add("d");                                              // [a, b, c, d]

String[] back = list.toArray(new String[0]);                // {"a", "b", "c", "d"}

Основы

1. Что такое массив

Массив это ряд пронумерованных ячеек. Во всех ячейках лежит один и тот же тип: только int, или только String, и так далее.

Представьте контейнер для яиц: в нём фиксированное число гнёзд, в каждом лежит одно яйцо, и гнёзда пронумерованы. Нумерация идёт с 0, а не с 1. Когда контейнер сделан, добавить в него гнездо нельзя: размер никогда не меняется.

// int[] numbers: ряд из 3 ячеек
//
//   значение: [10] [20] [30]
//   индекс:     0    1    2
//
// У первой ячейки индекс 0, у последней индекс 2 (размер минус 1).

2. Создание массива: со значениями или пустого

Два способа, в зависимости от того, что вы знаете:

  • Знаете значения: напишите их в фигурных скобках { }. Размер посчитается сам.
  • Знаете только размер: new Тип[размер]. Получите столько пустых ячеек.

Тип пишется с квадратными скобками: int[] это «массив int», String[] это «массив String».

// 1. Знаю значения
int[] numbers = {10, 20, 30};              // 3 ячейки: 10, 20, 30
String[] names = {"Anna", "Bob"};          // 2 ячейки: Anna, Bob

// 2. Знаю только размер: 5 пустых ячеек (для int они заполнены нулями)
int[] empty = new int[5];                  // [0, 0, 0, 0, 0]
String[] places = new String[3];           // [null, null, null]

// Размер пишется в [] после new. Это может быть переменная:
int size = 4;
double[] prices = new double[size];        // [0.0, 0.0, 0.0, 0.0]

3. Значения по умолчанию

Новый массив никогда не бывает «совсем пустым»: в каждой ячейке уже лежит значение
по умолчанию.
  int, long, short, byte  -> 0
  double, float           -> 0.0
  boolean                 -> false
  char                    -> символ с кодом 0 (невидимый)
  String и любой объект   -> null (значит «здесь пока ничего нет»)

Ловушка: в ячейке String лежит null, а вызов метода у null роняет программу.

boolean[] flags = new boolean[2];          // [false, false]
String[] names = new String[2];            // [null, null]

names[0] = "Anna";                         // [Anna, null]
// names[1].length();                      // NullPointerException: ячейка 1 всё ещё null

Работа с элементами

4. Прочитать и изменить элемент

Квадратные скобки с индексом: array[index]. Слева от = это запись значения, в любом другом месте это чтение. Размер массива это array.length (без скобок, в отличие от list.size()). Последний элемент это array[array.length - 1].

int[] numbers = {10, 20, 30};

int first = numbers[0];                    // 10: чтение
numbers[1] = 99;                           // запись: {10, 99, 30}
numbers[2] = numbers[2] + 1;               // прочитать, прибавить 1, записать обратно: {10, 99, 31}

int size = numbers.length;                 // 3
int last = numbers[numbers.length - 1];    // 31

5. Добавление элемента: массив не растёт

Добавить ячейку в массив нельзя: в контейнере для яиц фиксированное число гнёзд. numbers[3] = 40 для массива из 3 ячеек роняет программу.

Чтобы «добавить», создают НОВЫЙ массив побольше и копируют в него старые значения. Arrays.copyOf(old, newSize) делает оба шага сразу: создаёт больший массив и копирует значения. Новые ячейки пустые (0 для int). Затем новое значение записывают в свободную ячейку.

Если добавлять приходится часто, используйте List: он растёт сам (см. ListTheory).

int[] numbers = {10, 20, 30};

// Шаг 1: копия с ещё одной ячейкой
numbers = Arrays.copyOf(numbers, numbers.length + 1);   // {10, 20, 30, 0}

// Шаг 2: записать новое значение в свободную последнюю ячейку
numbers[numbers.length - 1] = 40;                       // {10, 20, 30, 40}

// То же самое со списком, без копирования:
List<Integer> list = new ArrayList<>(List.of(10, 20, 30));
list.add(40);                                           // [10, 20, 30, 40]

6. Вывод массива на экран

System.out.println(array) НЕ печатает значения: он печатает тип и адрес, что-то вроде [I@1b6d3586. Arrays.toString(array) печатает значения: [10, 20, 30].

int[] numbers = {10, 20, 30};

System.out.println(numbers);                    // [I@1b6d3586 (мусор)
System.out.println(Arrays.toString(numbers));   // [10, 20, 30]

7. Обход массива циклом

Чтобы сделать что-то с каждой ячейкой, используйте цикл (см. ForTheory).

  • for по индексу: когда нужна позиция или нужно менять ячейки.
  • for-each: когда значения только читаются.
int[] numbers = {10, 20, 30};

// По индексу: вывести позицию и значение
for (int i = 0; i < numbers.length; i++) {
    System.out.println(i + ": " + numbers[i]);  // 0: 10, 1: 20, 2: 30
}

// for-each: только значения
int sum = 0;
for (int number : numbers) {
    sum += number;
}
System.out.println(sum);                        // 60

8. ArrayIndexOutOfBoundsException, копирование и сравнение

Три классических неожиданности.

1) Индекс вне диапазона. У массива размера n индексы 0 .. n-1. Любой другой
   роняет программу с ArrayIndexOutOfBoundsException.
2) int[] b = a НЕ копирует. Это второе имя для того же массива: a и b это
   два имени одного контейнера, поэтому изменение b меняет a.
   Настоящая копия: Arrays.copyOf(a, a.length).
3) a == b проверяет, тот ли это же массив, а не одинаковы ли значения.
   Чтобы сравнить значения, используйте Arrays.equals(a, b).
int[] a = {1, 2, 3};

// 1) a[3] -> ArrayIndexOutOfBoundsException: Index 3 out of bounds for length 3

// 2) Второе имя, а не копия
int[] b = a;
b[0] = 100;                                    // a теперь тоже {100, 2, 3}!

int[] copy = Arrays.copyOf(a, a.length);       // настоящая копия
copy[0] = 5;                                   // a не меняется

// 3) Сравнение
int[] x = {1, 2};
int[] y = {1, 2};
System.out.println(x == y);                    // false: два разных массива
System.out.println(Arrays.equals(x, y));       // true: значения одинаковы

Массив или List?

9. Массив или List? Превращение одного в другой

Массив: фиксированный размер, может хранить примитивы (int[]), прост. List: растёт и уменьшается, имеет много готовых методов (add, remove, contains...), хранит объекты (List<Integer>).

Не уверены? Берите List. Массив берите, когда размер фиксирован и известен заранее.

  • массив объектов -> List: new ArrayList<>(Arrays.asList(array))
  • List -> массив объектов: list.toArray(new String[0]) Arrays.asList работает для String[] и Integer[], но не для int[].
String[] array = {"a", "b", "c"};

List<String> list = new ArrayList<>(Arrays.asList(array));  // [a, b, c]
list.add("d");                                              // [a, b, c, d]

String[] back = list.toArray(new String[0]);                // {"a", "b", "c", "d"}

Creating a list

1. What a List is

A List is an ordered collection that can contain duplicates. Every element has an index, starting at 0. Unlike an array, a List can grow and shrink.

Size: an array has .length, a List has .size(). Elements are objects: List<Integer>, not List<int> (see PrimitivesAndWrappersTheory).

// ["Anna", "Bob", "Anna"]
//    0       1      2      <- indexes

2. Creating a list: four ways

Think of a list as a paper shopping list: you can write new lines and cross lines out. There are four ways to get one:

  • Empty, fill it later: new ArrayList<>(). Like a new empty notebook.
    List<String> empty = new ArrayList<>();            // []
empty.add("milk");                                // [milk]
  • With starting items, and you can change it later: new ArrayList<>(List.of(...)). List.of(...) only provides the starting items; ArrayList copies them into a list you can change.
    List<String> fruits = new ArrayList<>(List.of("apple", "pear")); // [apple, pear]
fruits.add("plum");                                          // [apple, pear, plum]
  • With items that can NOT be changed: List.of(...). Good for data that never changes, like the days of the week.
    List<String> days = List.of("Mon", "Tue");   // [Mon, Tue]
days.add("Wed");                           // UnsupportedOperationException
  • From an array: new ArrayList<>(Arrays.asList(array)).
    String[] array = {"a", "b", "c"};
List<String> fromArray = new ArrayList<>(Arrays.asList(array)); // [a, b, c]

Which one? You will add or remove items later: the first, second or fourth way. The data is fixed: List.of.

What does "can change" mean? A list is changeable (the technical word is mutable) if after it is created you can still change what is inside: add an element (add), remove one (remove, clear), replace one (set) or reorder the list (sort). Reading is allowed in ANY list: get, size, contains, loops. A list that can NOT be changed (immutable, read-only) is filled once when it is created and stays exactly like that forever.

Why can't a List.of(...) list be changed? It is read-only on purpose. First, safety: a list of fixed data (days of the week, country codes) can't be broken by a mistake in another part of the program. Second, it can be shared freely: everybody sees the same data and nobody needs a protective copy. Third, it is simpler and faster inside, because it never has to grow. If you still try to change it, Java stops the program with UnsupportedOperationException ("this operation is not supported").

Note

What is new ArrayList<>() and why can't it be written differently?

  • ArrayList is a class: a ready-made "machine" that knows how to store and change items (it keeps them in an array inside). The word new tells Java: build a new object of this class in memory. So new ArrayList<>() means "build me a new empty list".
  • The variable type List is only a description of what a list can do (add, get, remove...). It has no code for storing items, so you can't build an object from it: new List<>() does not compile (error: List is abstract; cannot be instantiated). You must name a real class: ArrayList (the usual choice) or LinkedList.
  • List.of(...) is the exception: it is a ready method that builds a read-only list for you, so no new is needed.
  • The <> (diamond) saves you from writing the element type twice: Java takes it from the left side. More about the left and right side: section 3.
// 1. Empty
List<String> empty = new ArrayList<>();                          // []

// 2. With items, changeable
List<String> fruits = new ArrayList<>(List.of("apple", "pear")); // [apple, pear]
fruits.add("plum");                                              // OK: [apple, pear, plum]

// 3. With items, NOT changeable
List<String> days = List.of("Mon", "Tue");                       // [Mon, Tue]
days.get(0);                                                     // OK: reading is allowed
days.size();                                                     // OK
// days.add("Wed");                                              // UnsupportedOperationException
// days.remove(0);                                               // UnsupportedOperationException
// days.set(0, "Sun");                                           // UnsupportedOperationException

// 4. From an array
String[] array = {"a", "b", "c"};
List<String> fromArray = new ArrayList<>(Arrays.asList(array));  // [a, b, c]

// The wrong way: you can't build an object from an interface
// List<String> broken = new List<>();   // compile error: List is abstract; cannot be instantiated

3. List<String> names = new ArrayList<>(): what is on the left and on the right

  List<String>      - the TYPE of the variable (left side).
                      List is an interface: it only describes WHAT a list can do
                      (add, get, remove...), not HOW it is stored.
                      <String> says that the list holds Strings.
  names             - the variable name.
  new ArrayList<>() - the actual OBJECT created in memory (right side).
                      ArrayList is a class that implements List: it stores the
                      elements in an array inside and knows HOW to do all the operations.
  <>                - "diamond": the compiler infers <String> from the left side.

You can't write new List<>(): an interface can't be instantiated.

Why not ArrayList<String> names = new ArrayList<>()? It works, but declaring the variable as List lets you switch the implementation later (e.g. new LinkedList<>()) by changing only the right side. The rest of the code uses only List methods and stays the same. The same idea for methods: accept List<String> as a parameter, not ArrayList<String>.

ArrayList: stores elements in an array; fast get by index, slower insert/remove in the middle. The default choice.

List<String> names = new ArrayList<>(); // empty list

4. Immutable list: List.of

List.of(...) creates a list that cannot be changed. add, remove, set and sort throw UnsupportedOperationException.

Need a list you can change? Copy it: new ArrayList<>(List.of(...)).

List<String> fixed = List.of("Anna", "Bob");
// fixed.add("Eve"); // UnsupportedOperationException

List<String> changeable = new ArrayList<>(List.of("Anna", "Bob"));
changeable.add("Eve"); // OK -> [Anna, Bob, Eve]

Working with elements

5. Add, get, size, isEmpty

A list grows by itself: just call add. No size to choose, no copying.

  • add(x): put x at the END of the list.
  • add(index, x): put x at that place; everything after it moves one step to the right.
  • addAll(other): add all the elements of another list to the end. get(index) returns the element at the index. size() is the number of elements. isEmpty() is true when there is nothing in the list.
List<String> names = new ArrayList<>();

names.add("Anna");     // [Anna]
names.add("Bob");      // [Anna, Bob]
names.add(0, "Eve");   // [Eve, Anna, Bob]: Eve is in front, the others moved right
names.addAll(List.of("Tom", "Kate")); // [Eve, Anna, Bob, Tom, Kate]

names.get(0);          // "Eve"
names.size();          // 5
names.isEmpty();       // false

6. Change and remove: set, remove, clear

set(index, x) replaces the element and returns the old one. remove(index) deletes the element and shifts the rest to the left. remove("value") deletes the first match. clear() removes everything.

List<String> names = new ArrayList<>(List.of("Eve", "Anna", "Bob"));

names.set(1, "Alex");  // [Eve, Alex, Bob]
names.remove(0);       // by index -> [Alex, Bob]
names.remove("Bob");   // by value -> [Alex]
names.clear();         // []

7. Searching: contains, indexOf

contains(x) is true if the element is in the list. indexOf(x) is the index of the first match, or -1 if there is none. lastIndexOf(x) is the index of the last match.

List<String> names = new ArrayList<>(List.of("Anna", "Bob", "Anna"));

names.contains("Bob");      // true
names.indexOf("Anna");      // 0
names.lastIndexOf("Anna");  // 2
names.indexOf("Zed");       // -1: not found

8. Sorting: Collections.sort, reverse, max, min

The Collections class has helpers for lists. They need a changeable list (not List.of): sort and reverse change the list itself.

List<Integer> numbers = new ArrayList<>(List.of(3, 1, 2));

Collections.sort(numbers);          // [1, 2, 3]
Collections.reverse(numbers);       // [3, 2, 1]
Collections.max(numbers);           // 3
Collections.min(numbers);           // 1

Traps

9. remove(int) or remove(Object)?

A trap with List<Integer>. The list has two methods named remove: remove(int index) and remove(Object value). With a plain number Java picks the index.

List<Integer> list = new ArrayList<>(List.of(10, 20, 30));

list.remove(1);                    // index 1 -> removes 20 -> [10, 30]
list.remove(Integer.valueOf(10));  // the VALUE 10 -> [30]

10. IndexOutOfBoundsException

A list of size n has indexes 0 .. n-1. Anything else throws an exception. The last element is list.get(list.size() - 1).

List<String> names = new ArrayList<>(List.of("Anna", "Bob", "Eve"));

names.get(2);                   // "Eve", the last one
names.get(names.size() - 1);    // "Eve", the same
// names.get(3);                // IndexOutOfBoundsException: Index 3 out of bounds for length 3
// new ArrayList<String>().get(0); // the same for an empty list

Создание списка

1. Что такое List

List это упорядоченная коллекция, в которой могут быть дубликаты. У каждого элемента есть индекс, начиная с 0. В отличие от массива, List может расти и уменьшаться.

Размер: у массива .length, у List .size(). Элементы это объекты: List<Integer>, а не List<int> (см. PrimitivesAndWrappersTheory).

// ["Anna", "Bob", "Anna"]
//    0       1      2      <- индексы

2. Создание списка: четыре способа

Представьте список как бумажный список покупок: можно дописывать строки и вычёркивать их. Получить его можно четырьмя способами:

  • Пустой, заполнить позже: new ArrayList<>(). Как новая пустая тетрадь.
    List<String> empty = new ArrayList<>();            // []
empty.add("milk");                                // [milk]
  • С начальными элементами, и потом его можно менять: new ArrayList<>(List.of(...)). List.of(...) даёт только начальные элементы; ArrayList копирует их в список, который можно менять.
    List<String> fruits = new ArrayList<>(List.of("apple", "pear")); // [apple, pear]
fruits.add("plum");                                          // [apple, pear, plum]
  • С элементами, которые НЕЛЬЗЯ менять: List.of(...). Подходит для данных, которые не меняются, например дней недели.
    List<String> days = List.of("Mon", "Tue");   // [Mon, Tue]
days.add("Wed");                           // UnsupportedOperationException
  • Из массива: new ArrayList<>(Arrays.asList(array)).
    String[] array = {"a", "b", "c"};
List<String> fromArray = new ArrayList<>(Arrays.asList(array)); // [a, b, c]

Какой выбрать? Если потом будете добавлять или удалять элементы: первый, второй или четвёртый. Если данные фиксированы: List.of.

Что значит «можно менять»? Список изменяемый (технический термин mutable), если после создания в нём можно изменить содержимое: добавить элемент (add), удалить (remove, clear), заменить (set) или переставить (sort). Читать можно в ЛЮБОМ списке: get, size, contains, циклы. Список, который НЕЛЬЗЯ менять (immutable, «только для чтения»), заполняется один раз при создании и навсегда остаётся таким.

Почему список из List.of(...) нельзя менять? Он сделан «только для чтения» намеренно. Во-первых, безопасность: список с постоянными данными (дни недели, коды стран) нельзя испортить ошибкой в другой части программы. Во-вторых, им можно свободно делиться: все видят одни и те же данные, и защитная копия никому не нужна. В-третьих, внутри он проще и быстрее, потому что ему никогда не нужно расти. Если всё же попытаться его изменить, Java остановит программу с UnsupportedOperationException («эта операция не поддерживается»).

Заметка

Что такое new ArrayList<>() и почему нельзя написать иначе?

  • ArrayList это класс: готовая «машина», которая умеет хранить и менять элементы (внутри она держит их в массиве). Слово new говорит Java: создай в памяти новый объект этого класса. Значит, new ArrayList<>() означает «создай мне новый пустой список».
  • Тип переменной List это только описание того, что умеет список (add, get, remove...). В нём нет кода для хранения элементов, поэтому создать из него объект нельзя: new List<>() не компилируется (ошибка: List is abstract; cannot be instantiated). Нужно назвать настоящий класс: ArrayList (обычный выбор) или LinkedList.
  • List.of(...) это исключение: это готовый метод, который сам создаёт список «только для чтения», поэтому new не нужен.
  • Ромбовидный оператор <> избавляет от необходимости писать тип элементов дважды: Java берёт его из левой части. Подробнее про левую и правую часть: раздел 3.
// 1. Пустой
List<String> empty = new ArrayList<>();                          // []

// 2. С элементами, изменяемый
List<String> fruits = new ArrayList<>(List.of("apple", "pear")); // [apple, pear]
fruits.add("plum");                                              // OK: [apple, pear, plum]

// 3. С элементами, НЕизменяемый
List<String> days = List.of("Mon", "Tue");                       // [Mon, Tue]
days.get(0);                                                     // OK: чтение разрешено
days.size();                                                     // OK
// days.add("Wed");                                              // UnsupportedOperationException
// days.remove(0);                                               // UnsupportedOperationException
// days.set(0, "Sun");                                           // UnsupportedOperationException

// 4. Из массива
String[] array = {"a", "b", "c"};
List<String> fromArray = new ArrayList<>(Arrays.asList(array));  // [a, b, c]

// Неправильный способ: из интерфейса нельзя создать объект
// List<String> broken = new List<>();   // ошибка компиляции: List is abstract; cannot be instantiated

3. List<String> names = new ArrayList<>(): что слева и что справа

  List<String>      - ТИП переменной (левая часть).
                      List это интерфейс: он описывает только ЧТО умеет список
                      (add, get, remove...), но не КАК он хранится.
                      <String> говорит, что в списке лежат строки.
  names             - имя переменной.
  new ArrayList<>() - сам ОБЪЕКТ, созданный в памяти (правая часть).
                      ArrayList это класс, реализующий List: внутри он хранит
                      элементы в массиве и знает КАК выполнять все операции.
  <>                - «ромбовидный оператор» (diamond): компилятор сам определяет <String> по левой части.

Написать new List<>() нельзя: у интерфейса нельзя создать экземпляр.

Почему не ArrayList<String> names = new ArrayList<>()? Это работает, но если объявить переменную как List, реализацию можно потом заменить (например, на new LinkedList<>()), изменив только правую часть. Остальной код использует только методы List и остаётся прежним. Та же идея для методов: принимайте List<String> в параметре, а не ArrayList<String>.

ArrayList: хранит элементы в массиве; быстрый get по индексу, вставка и удаление в середине медленнее. Выбор по умолчанию.

List<String> names = new ArrayList<>(); // пустой список

4. Неизменяемый список: List.of

List.of(...) создаёт список, который нельзя менять. add, remove, set и sort бросают UnsupportedOperationException.

Нужен изменяемый список? Скопируйте его: new ArrayList<>(List.of(...)).

List<String> fixed = List.of("Anna", "Bob");
// fixed.add("Eve"); // UnsupportedOperationException

List<String> changeable = new ArrayList<>(List.of("Anna", "Bob"));
changeable.add("Eve"); // OK -> [Anna, Bob, Eve]

Работа с элементами

5. Добавить, получить, размер, пустой ли: add, get, size, isEmpty

Список растёт сам: достаточно вызвать add. Не нужно выбирать размер и копировать.

  • add(x): положить x в КОНЕЦ списка.
  • add(index, x): положить x на это место; всё, что после него, сдвигается на шаг вправо.
  • addAll(other): добавить в конец все элементы другого списка. get(index) возвращает элемент по индексу. size() это количество элементов. isEmpty() истинно, когда в списке ничего нет.
List<String> names = new ArrayList<>();

names.add("Anna");     // [Anna]
names.add("Bob");      // [Anna, Bob]
names.add(0, "Eve");   // [Eve, Anna, Bob]: Eve впереди, остальные сдвинулись вправо
names.addAll(List.of("Tom", "Kate")); // [Eve, Anna, Bob, Tom, Kate]

names.get(0);          // "Eve"
names.size();          // 5
names.isEmpty();       // false

6. Изменить и удалить: set, remove, clear

set(index, x) заменяет элемент и возвращает старый. remove(index) удаляет элемент и сдвигает остальные влево. remove("value") удаляет первое совпадение. clear() удаляет всё.

List<String> names = new ArrayList<>(List.of("Eve", "Anna", "Bob"));

names.set(1, "Alex");  // [Eve, Alex, Bob]
names.remove(0);       // по индексу -> [Alex, Bob]
names.remove("Bob");   // по значению -> [Alex]
names.clear();         // []

7. Поиск: contains, indexOf

contains(x) истинно, если элемент есть в списке. indexOf(x) это индекс первого совпадения или -1, если его нет. lastIndexOf(x) это индекс последнего совпадения.

List<String> names = new ArrayList<>(List.of("Anna", "Bob", "Anna"));

names.contains("Bob");      // true
names.indexOf("Anna");      // 0
names.lastIndexOf("Anna");  // 2
names.indexOf("Zed");       // -1: не найден

8. Сортировка: Collections.sort, reverse, max, min

В классе Collections есть вспомогательные методы для списков. Им нужен изменяемый список (не List.of): sort и reverse меняют сам список.

List<Integer> numbers = new ArrayList<>(List.of(3, 1, 2));

Collections.sort(numbers);          // [1, 2, 3]
Collections.reverse(numbers);       // [3, 2, 1]
Collections.max(numbers);           // 3
Collections.min(numbers);           // 1

Ловушки

9. remove(int) или remove(Object)?

Ловушка со списком List<Integer>. У списка два метода с именем remove: remove(int index) и remove(Object value). С обычным числом Java выбирает индекс.

List<Integer> list = new ArrayList<>(List.of(10, 20, 30));

list.remove(1);                    // индекс 1 -> удаляет 20 -> [10, 30]
list.remove(Integer.valueOf(10));  // ЗНАЧЕНИЕ 10 -> [30]

10. IndexOutOfBoundsException

У списка размера n индексы 0 .. n-1. Любой другой индекс бросает исключение. Последний элемент это list.get(list.size() - 1).

List<String> names = new ArrayList<>(List.of("Anna", "Bob", "Eve"));

names.get(2);                   // "Eve", последний
names.get(names.size() - 1);    // "Eve", то же самое
// names.get(3);                // IndexOutOfBoundsException: Index 3 out of bounds for length 3
// new ArrayList<String>().get(0); // то же для пустого списка

Basics

1. What a Set is

A Set is a collection of UNIQUE elements: the same value can be in it only once. It is good for two things: getting rid of duplicates and quickly checking whether a value is present.

Think of a guest list at the door: a name is either on the list or not. Writing the same name twice changes nothing.

A Set has no indexes: there is no set.get(0). HashSet is the most common Set.

// Added: Anna, Bob, Anna, Eve, Bob
// The set holds: Anna, Bob, Eve   (every name once, in any order)

2. Creating a set

  • Empty, fill it later: new HashSet<>().
  • From another collection: new HashSet<>(list). Duplicates disappear on the way.
  • Fixed items that can NOT be changed: Set.of(...). It throws an exception if you give it the same value twice.
// 1. Empty
Set<String> names = new HashSet<>();                      // {}

// 2. From a list
List<String> list = List.of("a", "b", "a");
Set<String> fromList = new HashSet<>(list);               // {a, b}

// 3. Fixed, NOT changeable
Set<String> fixed = Set.of("Mon", "Tue");                 // {Mon, Tue}
// fixed.add("Wed");                                      // UnsupportedOperationException
// Set.of("a", "a");                                      // IllegalArgumentException: duplicate element

3. Adding: duplicates are ignored

add(x) puts x into the set and returns a boolean:
  true  - the value was new and was added
  false - the value was already there, nothing changed
Set<String> names = new HashSet<>();

names.add("Anna");     // true,  {Anna}
names.add("Bob");      // true,  {Anna, Bob}
names.add("Anna");     // false, Anna is already there: still {Anna, Bob}

System.out.println(names.size());   // 2, not 3

Working with elements

4. Checking and removing: contains, remove, size

contains(x) answers "is x in the set?" and it is FAST, much faster than list.contains on a big collection. remove(x) deletes x (true if it was there). size() is the number of elements. isEmpty() and clear() work like in a List.

Set<String> names = new HashSet<>(List.of("Anna", "Bob", "Eve"));

names.contains("Bob");     // true
names.contains("Zed");     // false

names.remove("Bob");       // true,  {Anna, Eve}
names.remove("Zed");       // false, nothing to remove
names.size();              // 2

names.clear();             // {}
names.isEmpty();           // true

5. Removing duplicates from a list

The classic use of a Set. Put the list into a HashSet: the duplicates vanish. If you need a list again, copy the set back into an ArrayList.

To keep the original order of the first appearances use LinkedHashSet (see 7).

List<Integer> numbers = List.of(1, 2, 2, 3, 3, 3);

Set<Integer> unique = new HashSet<>(numbers);                    // {1, 2, 3}
List<Integer> withoutDuplicates = new ArrayList<>(unique);       // [1, 2, 3]

// How many different values are there?
System.out.println(unique.size());                               // 3

// Are there duplicates at all?
boolean hasDuplicates = numbers.size() != unique.size();         // true

6. Looping over a set

A Set has no indexes, so use for-each (see ForTheory). The order of the elements in a HashSet is not guaranteed.

Set<String> names = new HashSet<>(List.of("Anna", "Bob", "Eve"));

for (String name : names) {
    System.out.println(name);      // all three, in any order
}

// for (int i = 0; i < names.size(); i++) { names.get(i) }  // does not compile: no get(i)

Kinds of Set

7. HashSet, LinkedHashSet, TreeSet

All three are used the same way. The difference is the order of the elements.

  HashSet         - no guaranteed order. The default choice, the fastest.
  LinkedHashSet   - keeps the insertion order.
  TreeSet         - keeps the elements sorted (A to Z, smallest to largest).
Set<String> hash = new HashSet<>();
Set<String> linked = new LinkedHashSet<>();
Set<String> tree = new TreeSet<>();

// After add("Bob"), add("Anna"), add("Eve"):
//   HashSet:       any order
//   LinkedHashSet: [Bob, Anna, Eve]
//   TreeSet:       [Anna, Bob, Eve]

Traps

8. No index, no order, equals and hashCode

Three things to remember.

1) No index and no order in a HashSet: you can't ask for "the first element".
2) A set decides "is it the same?" with equals() and hashCode(). String and Integer
   do it right. For your own classes you must write both methods, otherwise two
   "equal" objects both get into the set.
3) Don't change a set while you loop over it with for-each: ConcurrentModificationException.
   Use an Iterator or removeIf (see ListTheory).
Set<String> names = new HashSet<>();
names.add("Anna");
names.add("anna");           // a different string (case matters) -> both are stored
names.size();                // 2

Choosing

9. List, Set or Map?

  List - ordered, access by index, duplicates allowed.
         "A queue of people": the order and repeats matter.
  Set  - unique elements, fast "is it there?", no index.
         "A guest list": only presence matters.
  Map  - pairs key -> value, find a value by its key.
         "A phone book": name -> number.

Technically List and Set belong to the Collection family (they have add, remove, contains, size). Map is a separate interface and does not extend Collection (see MapTheory).

List<String> queue = new ArrayList<>();   // order and duplicates matter
Set<String> guests = new HashSet<>();     // only "is this name here?" matters

1. Что такое Set

Set это коллекция УНИКАЛЬНЫХ элементов: одно и то же значение в ней может быть только один раз. Она хороша для двух вещей: избавляться от дубликатов и быстро проверять, есть ли значение.

// В множестве: Anna, Bob, Eve   (каждое имя один раз, в любом порядке)

2. Создание множества

  • Пустое, заполнить позже: new HashSet<>().
  • Из другой коллекции: new HashSet<>(list). Дубликаты исчезают по пути.

// 2. Из списка

// 3. Фиксированное, НЕизменяемое
Set<String> fixed = Set.of("Mon", "Tue");                 // {Mon, Tue}
// fixed.add("Wed");                                      // UnsupportedOperationException
// Set.of("a", "a");                                      // IllegalArgumentException: duplicate element

3. Добавление: дубликаты игнорируются

add(x) кладёт x в множество и возвращает boolean:
  true  - значение было новым и добавилось
  false - значение уже было, ничего не изменилось
Set<String> names = new HashSet<>();

names.add("Anna");     // true,  {Anna}
names.add("Bob");      // true,  {Anna, Bob}
names.add("Anna");     // false, Anna уже есть: по-прежнему {Anna, Bob}

System.out.println(names.size());   // 2, а не 3

Работа с элементами

4. Проверка и удаление: contains, remove, size

contains(x) отвечает «x есть в множестве?» и работает БЫСТРО, намного быстрее, чем list.contains на большой коллекции. remove(x) удаляет x (true, если он был). size() это количество элементов. isEmpty() и clear() работают как в List.

Set<String> names = new HashSet<>(List.of("Anna", "Bob", "Eve"));

names.contains("Bob");     // true
names.contains("Zed");     // false

names.remove("Bob");       // true,  {Anna, Eve}
names.remove("Zed");       // false, удалять нечего
names.size();              // 2

names.clear();             // {}
names.isEmpty();           // true

5. Удаление дубликатов из списка

Классическое применение Set. Положите список в HashSet: дубликаты исчезнут. Если снова нужен список, скопируйте множество обратно в ArrayList.

Чтобы сохранить исходный порядок первых появлений, используйте LinkedHashSet (см. 7).

List<Integer> numbers = List.of(1, 2, 2, 3, 3, 3);

// Есть ли вообще дубликаты?

Все три используются одинаково. Разница в порядке элементов.

  HashSet         - порядок не гарантирован. Выбор по умолчанию, самый быстрый.
  LinkedHashSet   - сохраняет порядок добавления.

8. Нет индекса, нет порядка, equals и hashCode

Три вещи, которые нужно помнить.

1) В HashSet нет индекса и нет порядка: нельзя попросить «первый элемент».
2) Множество решает «это то же самое?» через equals() и hashCode(). У String и Integer
   они сделаны правильно. Для своих классов нужно написать оба метода, иначе два
   «равных» объекта попадут в множество оба.

   Используйте Iterator или removeIf (см. ListTheory).

Basics

1. What a Map is

A Map stores key -> value pairs, like a dictionary. You find a value by its key. Keys are unique. Values can repeat. Lookup by key is fast.

Generics: Map<KeyType, ValueType>. Primitives need wrappers: Map<String, Integer>, not Map<String, int> (see PrimitivesAndWrappersTheory).

Map is not a List: there are no indexes and you can't write map.get(0).

Technically Map is a separate interface: it does NOT extend Collection (List and Set do). That is why a Map has no add(x) (there is put(key, value)) and you can't loop over it directly (see section 6).

A typical example: an employee name and the salary of this employee.

// Employee name -> salary:
//   "Anna" -> 3000
//   "Bob"  -> 2500
Map<String, Integer> salaries = new HashMap<>();
salaries.put("Anna", 3000);
salaries.put("Bob", 2500);

2. Put and get

put(key, value) adds a pair. If the key already exists, its value is OVERWRITTEN. get(key) returns the value.

Map<String, Integer> ages = new HashMap<>();

ages.put("Anna", 25);   // {Anna=25}
ages.put("Bob", 30);    // {Anna=25, Bob=30}
ages.put("Anna", 26);   // same key -> {Anna=26, Bob=30}

ages.get("Anna");       // 26
ages.size();            // 2: still two keys

3. Missing key: null and getOrDefault

get returns null when the key is not found. getOrDefault(key, x) returns x instead.

A trap: unboxing null. int age = ages.get("Zed") throws NullPointerException, because null cannot become an int (see PrimitivesAndWrappersTheory).

Map<String, Integer> ages = new HashMap<>();
ages.put("Anna", 26);

Integer unknown = ages.get("Zed");        // null
int safe = ages.getOrDefault("Zed", 0);   // 0
// int crash = ages.get("Zed");           // NullPointerException

4. Checking a key: containsKey

containsKey(key) is true if the key is in the map. containsValue(value) checks values (it is slow: it looks through all of them).

Map<String, Integer> ages = new HashMap<>();
ages.put("Anna", 26);

ages.containsKey("Anna");   // true
ages.containsKey("Zed");    // false
ages.containsValue(26);     // true

Kinds of Map

5. HashMap, LinkedHashMap, TreeMap

All three are used the same way. The difference is the order of the pairs.

  HashMap         - no guaranteed order. The default choice, the fastest.
  LinkedHashMap   - keeps the insertion order.
  TreeMap         - keeps the keys sorted (A to Z, smallest to largest).

Map.of(...) creates an immutable map (put throws UnsupportedOperationException).

Map<String, Integer> hash = new HashMap<>();
Map<String, Integer> linked = new LinkedHashMap<>();
Map<String, Integer> tree = new TreeMap<>();

// After put("Bob", 1), put("Anna", 2), put("Eve", 3):
//   HashMap:       any order
//   LinkedHashMap: {Bob=1, Anna=2, Eve=3}
//   TreeMap:       {Anna=2, Bob=1, Eve=3}

Looping

6. Iterating: entrySet, keySet, values

A Map can't be looped over directly. Choose what you need:
  entrySet() - key and value together (pairs)
  keySet()   - only keys
  values()   - only values
Map<String, Integer> ages = new LinkedHashMap<>();
ages.put("Anna", 26);
ages.put("Bob", 30);

// Pairs: Anna=26, Bob=30
for (Map.Entry<String, Integer> e : ages.entrySet()) {
    System.out.println(e.getKey() + "=" + e.getValue());
}

// Keys: Anna, Bob
for (String name : ages.keySet()) {
    System.out.println(name);
}

// Values: 26, 30
for (int age : ages.values()) {
    System.out.println(age);
}

Traps

7. Keys must be unique and comparable by equals/hashCode

A Map finds a key using equals() and hashCode(). String and Integer have them done right, so use them as keys. For your own classes you must write both methods, otherwise two "equal" objects become two different keys.

Do not change an object after using it as a key: its hashCode changes and the map will not find it anymore.

Map<String, Integer> map = new HashMap<>();
map.put("Anna", 1);
map.put("anna", 2);  // different key: String is case-sensitive -> 2 entries
map.size();          // 2

Основы

1. Что такое Map

Map хранит пары ключ -> значение, как словарь. Значение находят по ключу. Ключи уникальны. Значения могут повторяться. Поиск по ключу быстрый.

Generics: Map<ТипКлюча, ТипЗначения>. Примитивам нужны обёртки: Map<String, Integer>, а не Map<String, int> (см. PrimitivesAndWrappersTheory).

Map это не List: индексов нет, и map.get(0) писать нельзя.

Технически Map это отдельный интерфейс: он НЕ наследует Collection (а List и Set наследуют). Поэтому у Map нет add(x) (есть put(key, value)), и по нему нельзя пройти циклом напрямую (см. раздел 6).

Типичный пример: имя сотрудника и его зарплата.

// Employee name -> salary:
//   "Anna" -> 3000
//   "Bob"  -> 2500
Map<String, Integer> salaries = new HashMap<>();
salaries.put("Anna", 3000);
salaries.put("Bob", 2500);

2. Положить и получить: put и get

put(key, value) добавляет пару. Если ключ уже есть, его значение ПЕРЕЗАПИСЫВАЕТСЯ. get(key) возвращает значение.

Map<String, Integer> ages = new HashMap<>();

ages.put("Anna", 25);   // {Anna=25}
ages.put("Bob", 30);    // {Anna=25, Bob=30}
ages.put("Anna", 26);   // тот же ключ -> {Anna=26, Bob=30}

ages.get("Anna");       // 26
ages.size();            // 2: по-прежнему два ключа

3. Нет ключа: null и getOrDefault

get возвращает null, если ключ не найден. getOrDefault(key, x) вместо этого возвращает x.

Ловушка: распаковка null. int age = ages.get("Zed") бросает NullPointerException, потому что null нельзя превратить в int (см. PrimitivesAndWrappersTheory).

Map<String, Integer> ages = new HashMap<>();
ages.put("Anna", 26);

Integer unknown = ages.get("Zed");        // null
int safe = ages.getOrDefault("Zed", 0);   // 0
// int crash = ages.get("Zed");           // NullPointerException

4. Проверка ключа: containsKey

containsKey(key) истинно, если ключ есть в карте. containsValue(value) проверяет значения (это медленно: перебираются все).

Map<String, Integer> ages = new HashMap<>();
ages.put("Anna", 26);

ages.containsKey("Anna");   // true
ages.containsKey("Zed");    // false
ages.containsValue(26);     // true

Виды Map

5. HashMap, LinkedHashMap, TreeMap

Все три используются одинаково. Разница в порядке пар.

  HashMap         - порядок не гарантирован. Выбор по умолчанию, самый быстрый.
  LinkedHashMap   - сохраняет порядок добавления.
  TreeMap         - хранит ключи отсортированными (от A до Z, от меньшего к большему).

Map.of(...) создаёт неизменяемую карту (put бросает UnsupportedOperationException).

Map<String, Integer> hash = new HashMap<>();
Map<String, Integer> linked = new LinkedHashMap<>();
Map<String, Integer> tree = new TreeMap<>();

// После put("Bob", 1), put("Anna", 2), put("Eve", 3):
//   HashMap:       любой порядок
//   LinkedHashMap: {Bob=1, Anna=2, Eve=3}
//   TreeMap:       {Anna=2, Bob=1, Eve=3}

Обход

6. Перебор: entrySet, keySet, values

Напрямую по Map цикл не пройти. Выберите, что нужно:
  entrySet() - ключ и значение вместе (пары)
  keySet()   - только ключи
  values()   - только значения
Map<String, Integer> ages = new LinkedHashMap<>();
ages.put("Anna", 26);
ages.put("Bob", 30);

// Пары: Anna=26, Bob=30
for (Map.Entry<String, Integer> e : ages.entrySet()) {
    System.out.println(e.getKey() + "=" + e.getValue());
}

// Ключи: Anna, Bob
for (String name : ages.keySet()) {
    System.out.println(name);
}

// Значения: 26, 30
for (int age : ages.values()) {
    System.out.println(age);
}

7. Ключи уникальны и сравниваются через equals/hashCode

Map находит ключ с помощью equals() и hashCode(). У String и Integer они реализованы правильно, поэтому используйте их как ключи. Для своих классов нужно написать оба метода, иначе два «равных» объекта станут двумя разными ключами.

Не меняйте объект после того, как использовали его как ключ: изменится hashCode, и карта его больше не найдёт.

Map<String, Integer> map = new HashMap<>();
map.put("Anna", 1);
map.put("anna", 2);  // другой ключ: String учитывает регистр -> 2 записи
map.size();          // 2

Basics

1. What a stream is

A stream is a way to process a collection step by step, like a conveyor belt:

  source  ->  station  ->  station  ->  ...  ->  result
  (list)      filter       map                    (list, number, text...)
  • The source is a List, Set, array and so on.
  • Stations (intermediate operations) take elements, filter or change them and pass them on.
  • The last step (terminal operation) collects the result. Only then the conveyor starts.

A stream does NOT change the source list. It gives you a new result. It replaces many for-loops with short, readable code: "from the invoices take the big ones, add up their totals".

List<Integer> totals = List.of(5, 12, 8, 20, 3);

// "From the invoice totals take those above 7 and make a list"
List<Integer> big = totals.stream()    // source
        .filter(t -> t > 7)            // station: keep big ones
        .toList();                     // end: a list [12, 8, 20]

// The same with a loop (longer):
// List<Integer> big = new ArrayList<>();
// for (int t : totals) { if (t > 7) big.add(t); }

2. Creating a stream

  • from a List or Set: list.stream()
  • from an array: Arrays.stream(array)
  • from values: Stream.of("a", "b", "c")
  • a range of numbers: IntStream.range(1, 6) gives 1, 2, 3, 4, 5 (the end is NOT included); IntStream.rangeClosed(1, 5) gives 1..5 (the end is included)

A Map has no stream(): use map.entrySet().stream() or map.values().stream().

List<String> names = List.of("Anna", "Bob", "Eve");
int[] numbers = {10, 20, 30};

Stream<String> fromList = names.stream();
IntStream fromArray = java.util.Arrays.stream(numbers);
Stream<String> fromValues = Stream.of("a", "b", "c");
IntStream range = IntStream.range(1, 6);                // 1, 2, 3, 4, 5

3. Lambda: a tiny function

Streams are fed with small functions written as a lambda: parameters -> result.

  x -> x * 2            one parameter, returns x * 2
  (a, b) -> a + b       two parameters need brackets
  x -> { ...; return y; }  a block when one expression is not enough

Read the arrow as "goes to": t -> t > 7 is "t goes to (t is greater than 7)". The name of the parameter is up to you.

Method reference is a shorter lambda that only calls one method:
  String::toUpperCase    is the same as   s -> s.toUpperCase()
  String::length         is the same as   s -> s.length()
  System.out::println    is the same as   x -> System.out.println(x)
List<String> names = List.of("Anna", "Bob", "Eve");

names.stream().map(s -> s.toUpperCase());      // lambda
names.stream().map(String::toUpperCase);       // method reference: the same

Intermediate operations: the stations of the conveyor

4. filter: keep only the matching elements

filter takes a condition (a lambda that returns true or false) and lets through only the elements for which it is true. The rest are thrown away.

List<Integer> totals = List.of(5, 12, 8, 20, 3);
List<String> names = List.of("Anna", "Bob", "Alex", "Eve");

List<Integer> big = totals.stream().filter(t -> t > 7).toList();        // [12, 8, 20]
List<String> onA = names.stream().filter(n -> n.startsWith("A")).toList(); // [Anna, Alex]

5. map: transform every element

map takes a function and applies it to every element. The number of elements stays the same, but the elements (and even their type) can change.

List<String> names = List.of("Anna", "Bob", "Eve");
List<Integer> prices = List.of(5, 12, 8);

List<String> upper = names.stream().map(String::toUpperCase).toList();  // [ANNA, BOB, EVE]
List<Integer> lengths = names.stream().map(String::length).toList();    // [4, 3, 3]: String -> Integer
List<Integer> cents = prices.stream().map(p -> p * 100).toList();       // [500, 1200, 800]

// Stations can be chained: filter first, then map
List<String> result = names.stream()
        .filter(n -> n.length() > 3)
        .map(String::toUpperCase)
        .toList();                                                      // [ANNA]

6. sorted, distinct, limit, skip

  sorted()                         - ascending order (numbers, strings)
  sorted(Comparator.reverseOrder()) - descending order
  distinct()                       - drop duplicates
  limit(n)                         - take only the first n elements
  skip(n)                          - skip the first n elements
List<Integer> totals = List.of(5, 12, 8, 12, 3);

totals.stream().sorted().toList();                                   // [3, 5, 8, 12, 12]
totals.stream().sorted(Comparator.reverseOrder()).toList();          // [12, 12, 8, 5, 3]
totals.stream().distinct().toList();                                 // [5, 12, 8, 3]
totals.stream().limit(2).toList();                                   // [5, 12]
totals.stream().skip(3).toList();                                    // [12, 3]

// "The top 3 biggest totals":
totals.stream().sorted(Comparator.reverseOrder()).limit(3).toList(); // [12, 12, 8]

Terminal operations: the end of the conveyor

7. toList and collect: get a collection back

toList() ends the stream and gives a List. The result can NOT be changed (add throws UnsupportedOperationException). If you need a changeable list, wrap it: new ArrayList<>(...).

collect(...) is the general way, with ready collectors from the Collectors class:
  Collectors.toList()         - a changeable List
  Collectors.toSet()          - a Set (duplicates vanish)
  Collectors.joining(", ")    - one String with all elements, with a separator

(toList() needs Java 16 or newer.)

List<String> names = List.of("Anna", "Bob", "Eve");

List<String> list = names.stream().toList();                          // [Anna, Bob, Eve]
java.util.Set<String> set = names.stream().collect(Collectors.toSet());
String text = names.stream().collect(Collectors.joining(", "));       // "Anna, Bob, Eve"

8. count, sum, average, min, max

These operations end the stream and give a single value.
  count()                 - how many elements (the result is a long)
  mapToInt(...).sum()     - the sum of numbers
  mapToInt(...).average() - the average (an OptionalDouble: the list may be empty)
  max(...) / min(...)     - the biggest / the smallest (an Optional: the list may be empty)

mapToInt(Integer::intValue) turns a Stream<Integer> into an IntStream, which has sum() and average().

List<Integer> totals = List.of(5, 12, 8, 20, 3);

long howMany = totals.stream().filter(t -> t > 7).count();                  // 3
int sum = totals.stream().mapToInt(Integer::intValue).sum();                // 48
double average = totals.stream().mapToInt(Integer::intValue)
        .average().orElse(0);                                               // 9.6
int max = totals.stream().max(Integer::compare).orElse(-1);                 // 20
int min = totals.stream().min(Integer::compare).orElse(-1);                 // 3

// orElse(x) is the value for an empty list: without it you get an Optional box.

9. anyMatch, allMatch, noneMatch, findFirst

Questions about the elements:
  anyMatch(cond)   - is there AT LEAST ONE element that matches? (true/false)
  allMatch(cond)   - do ALL elements match? (true for an empty list)
  noneMatch(cond)  - does NO element match?
  findFirst()      - the first element, as an Optional (the stream may be empty).
                     Take the value with orElse(default) or get().
List<Integer> totals = List.of(5, 12, 8, 20, 3);

boolean hasBig = totals.stream().anyMatch(t -> t > 15);                      // true
boolean allPositive = totals.stream().allMatch(t -> t > 0);                  // true
boolean noHuge = totals.stream().noneMatch(t -> t > 100);                    // true

Optional<Integer> first = totals.stream().filter(t -> t > 10).findFirst();   // Optional[12]
int firstOrDefault = totals.stream().filter(t -> t > 100).findFirst().orElse(-1); // -1

10. forEach

forEach does something with every element (print it, save it). It returns nothing. Use it for actions, not for collecting results: for results use toList() or collect.

List<String> names = List.of("Anna", "Bob", "Eve");

names.stream().forEach(System.out::println);       // Anna, Bob, Eve
names.forEach(System.out::println);                // a List has forEach too: the same

Grouping

11. groupingBy and counting

collect(Collectors.groupingBy(...)) splits elements into groups and returns a Map: the key is the group, the value is a list of its elements. With counting() the value is just the number of elements in the group.

List<String> countries = List.of("Brazil", "USA", "Brazil", "Canada", "USA", "Brazil");

// How many customers from each country?
Map<String, Long> count = countries.stream()
        .collect(Collectors.groupingBy(c -> c, Collectors.counting()));
// {Brazil=3, USA=2, Canada=1}  (the order of a HashMap is not guaranteed)

// Group the words by their length:
List<String> words = List.of("hi", "yo", "hello", "world", "a");
Map<Integer, List<String>> byLength = words.stream()
        .collect(Collectors.groupingBy(String::length));
// {1=[a], 2=[hi, yo], 5=[hello, world]}

Traps

12. One use only, no terminal operation, effectively final

Three classic traps.

1) A stream can be used ONCE. A second use throws IllegalStateException
   ("stream has already been operated upon or closed"). Make a new stream from the list.
2) Without a terminal operation nothing happens. filter and map only describe the
   conveyor; it starts when you call toList, count, forEach and so on.
3) A lambda can only read local variables that never change (effectively final).
   You can't count with an outside counter++ inside a lambda. Use count() or sum() instead.
List<Integer> totals = List.of(5, 12, 8);

Stream<Integer> stream = totals.stream();
stream.count();
// stream.count();                      // IllegalStateException

totals.stream().filter(t -> t > 7);     // does nothing: no terminal operation

// int counter = 0;
// totals.forEach(t -> counter++);      // does not compile: counter is not effectively final
long counter = totals.stream().filter(t -> t > 7).count();   // the right way

Основы

1. Что такое поток (stream)

Поток это способ обрабатывать коллекцию по шагам, как конвейер:

  источник  ->  станция  ->  станция  ->  ...  ->  результат
  (список)      filter       map                   (список, число, текст...)
  • Источник это List, Set, массив и так далее.
  • Станции (промежуточные операции) берут элементы, фильтруют или меняют их и передают дальше.
  • Последний шаг (терминальная операция) собирает результат. Только тогда конвейер запускается.

Поток НЕ меняет исходный список. Он даёт новый результат. Он заменяет много циклов for коротким читаемым кодом: «из счетов возьми большие, сложи их суммы».

List<Integer> totals = List.of(5, 12, 8, 20, 3);

// «Из сумм счетов возьми те, что больше 7, и сделай список»
List<Integer> big = totals.stream()    // источник
        .filter(t -> t > 7)            // станция: оставить большие
        .toList();                     // конец: список [12, 8, 20]

// То же самое циклом (длиннее):
// List<Integer> big = new ArrayList<>();
// for (int t : totals) { if (t > 7) big.add(t); }

2. Создание потока

  • из List или Set: list.stream()
  • из массива: Arrays.stream(array)
  • из значений: Stream.of("a", "b", "c")
  • диапазон чисел: IntStream.range(1, 6) даёт 1, 2, 3, 4, 5 (конец НЕ включается); IntStream.rangeClosed(1, 5) даёт 1..5 (конец включается)

У Map нет stream(): используйте map.entrySet().stream() или map.values().stream().

List<String> names = List.of("Anna", "Bob", "Eve");
int[] numbers = {10, 20, 30};

Stream<String> fromList = names.stream();
IntStream fromArray = java.util.Arrays.stream(numbers);
Stream<String> fromValues = Stream.of("a", "b", "c");
IntStream range = IntStream.range(1, 6);                // 1, 2, 3, 4, 5

3. Лямбда: крошечная функция

В потоки передают маленькие функции, записанные как лямбда: параметры -> результат.

  x -> x * 2            один параметр, возвращает x * 2
  (a, b) -> a + b       для двух параметров нужны скобки
  x -> { ...; return y; }  блок, когда одного выражения мало

Читайте стрелку как «переходит в»: t -> t > 7 это «t переходит в (t больше 7)». Имя параметра можно выбрать любое.

Ссылка на метод это более короткая лямбда, которая только вызывает один метод:
  String::toUpperCase    то же самое, что   s -> s.toUpperCase()
  String::length         то же самое, что   s -> s.length()
  System.out::println    то же самое, что   x -> System.out.println(x)
List<String> names = List.of("Anna", "Bob", "Eve");

names.stream().map(s -> s.toUpperCase());      // лямбда
names.stream().map(String::toUpperCase);       // ссылка на метод: то же самое

Промежуточные операции: станции конвейера

4. filter: оставить только подходящие элементы

filter принимает условие (лямбду, которая возвращает true или false) и пропускает только те элементы, для которых оно истинно. Остальные отбрасываются.

List<Integer> totals = List.of(5, 12, 8, 20, 3);
List<String> names = List.of("Anna", "Bob", "Alex", "Eve");

List<Integer> big = totals.stream().filter(t -> t > 7).toList();        // [12, 8, 20]
List<String> onA = names.stream().filter(n -> n.startsWith("A")).toList(); // [Anna, Alex]

5. map: преобразовать каждый элемент

map принимает функцию и применяет её к каждому элементу. Количество элементов остаётся тем же, но сами элементы (и даже их тип) могут измениться.

List<String> names = List.of("Anna", "Bob", "Eve");
List<Integer> prices = List.of(5, 12, 8);

List<String> upper = names.stream().map(String::toUpperCase).toList();  // [ANNA, BOB, EVE]
List<Integer> lengths = names.stream().map(String::length).toList();    // [4, 3, 3]: String -> Integer
List<Integer> cents = prices.stream().map(p -> p * 100).toList();       // [500, 1200, 800]

// Станции можно соединять в цепочку: сначала filter, потом map
List<String> result = names.stream()
        .filter(n -> n.length() > 3)
        .map(String::toUpperCase)
        .toList();                                                      // [ANNA]

6. sorted, distinct, limit, skip

  sorted()                         - по возрастанию (числа, строки)
  sorted(Comparator.reverseOrder()) - по убыванию
  distinct()                       - убрать дубликаты
  limit(n)                         - взять только первые n элементов
  skip(n)                          - пропустить первые n элементов
List<Integer> totals = List.of(5, 12, 8, 12, 3);

totals.stream().sorted().toList();                                   // [3, 5, 8, 12, 12]
totals.stream().sorted(Comparator.reverseOrder()).toList();          // [12, 12, 8, 5, 3]
totals.stream().distinct().toList();                                 // [5, 12, 8, 3]
totals.stream().limit(2).toList();                                   // [5, 12]
totals.stream().skip(3).toList();                                    // [12, 3]

// «Топ-3 самых больших суммы»:
totals.stream().sorted(Comparator.reverseOrder()).limit(3).toList(); // [12, 12, 8]

Терминальные операции: конец конвейера

7. toList и collect: получить коллекцию обратно

toList() завершает поток и выдаёт List. Результат НЕЛЬЗЯ менять (add бросает UnsupportedOperationException). Если нужен изменяемый список, оберните: new ArrayList<>(...).

collect(...) это общий способ, с готовыми коллекторами из класса Collectors:
  Collectors.toList()         - изменяемый List
  Collectors.toSet()          - Set (дубликаты исчезают)
  Collectors.joining(", ")    - одна строка со всеми элементами через разделитель

(toList() требует Java 16 или новее.)

List<String> names = List.of("Anna", "Bob", "Eve");

List<String> list = names.stream().toList();                          // [Anna, Bob, Eve]
java.util.Set<String> set = names.stream().collect(Collectors.toSet());
String text = names.stream().collect(Collectors.joining(", "));       // "Anna, Bob, Eve"

8. count, sum, average, min, max

Эти операции завершают поток и дают одно значение.
  count()                 - сколько элементов (результат long)
  mapToInt(...).sum()     - сумма чисел
  mapToInt(...).average() - среднее (OptionalDouble: список может быть пустым)
  max(...) / min(...)     - наибольший / наименьший (Optional: список может быть пустым)

mapToInt(Integer::intValue) превращает Stream<Integer> в IntStream, у которого есть sum() и average().

List<Integer> totals = List.of(5, 12, 8, 20, 3);

long howMany = totals.stream().filter(t -> t > 7).count();                  // 3
int sum = totals.stream().mapToInt(Integer::intValue).sum();                // 48
double average = totals.stream().mapToInt(Integer::intValue)
        .average().orElse(0);                                               // 9.6
int max = totals.stream().max(Integer::compare).orElse(-1);                 // 20
int min = totals.stream().min(Integer::compare).orElse(-1);                 // 3

// orElse(x) это значение для пустого списка: без него вы получите «коробку» Optional.

9. anyMatch, allMatch, noneMatch, findFirst

Вопросы об элементах:
  anyMatch(cond)   - есть ХОТЯ БЫ ОДИН подходящий элемент? (true/false)
  allMatch(cond)   - подходят ли ВСЕ элементы? (true для пустого списка)
  noneMatch(cond)  - НЕ подходит ни один элемент?
  findFirst()      - первый элемент, в виде Optional (поток может быть пустым).
                     Значение берут через orElse(default) или get().
List<Integer> totals = List.of(5, 12, 8, 20, 3);

boolean hasBig = totals.stream().anyMatch(t -> t > 15);                      // true
boolean allPositive = totals.stream().allMatch(t -> t > 0);                  // true
boolean noHuge = totals.stream().noneMatch(t -> t > 100);                    // true

Optional<Integer> first = totals.stream().filter(t -> t > 10).findFirst();   // Optional[12]
int firstOrDefault = totals.stream().filter(t -> t > 100).findFirst().orElse(-1); // -1

10. forEach

forEach что-то делает с каждым элементом (печатает, сохраняет). Он ничего не возвращает. Используйте его для действий, а не для сбора результатов: для результатов есть toList() и collect.

List<String> names = List.of("Anna", "Bob", "Eve");

names.stream().forEach(System.out::println);       // Anna, Bob, Eve
names.forEach(System.out::println);                // у List тоже есть forEach: то же самое

Группировка

11. groupingBy и counting

collect(Collectors.groupingBy(...)) делит элементы на группы и возвращает Map: ключ это группа, значение это список её элементов. С counting() значение это просто количество элементов в группе.

List<String> countries = List.of("Brazil", "USA", "Brazil", "Canada", "USA", "Brazil");

// Сколько клиентов из каждой страны?
Map<String, Long> count = countries.stream()
        .collect(Collectors.groupingBy(c -> c, Collectors.counting()));
// {Brazil=3, USA=2, Canada=1}  (порядок в HashMap не гарантирован)

// Сгруппировать слова по длине:
List<String> words = List.of("hi", "yo", "hello", "world", "a");
Map<Integer, List<String>> byLength = words.stream()
        .collect(Collectors.groupingBy(String::length));
// {1=[a], 2=[hi, yo], 5=[hello, world]}

Ловушки

12. Один раз, нет терминальной операции, effectively final

Три классические ловушки.

1) Поток можно использовать ОДИН раз. Повторное использование бросает IllegalStateException
   ("stream has already been operated upon or closed"). Создайте новый поток из списка.
2) Без терминальной операции ничего не происходит. filter и map только описывают
   конвейер; он запускается, когда вы вызываете toList, count, forEach и так далее.
3) Лямбда может только читать локальные переменные, которые не меняются (effectively final).
   Считать внешним counter++ внутри лямбды нельзя. Используйте count() или sum().
List<Integer> totals = List.of(5, 12, 8);

Stream<Integer> stream = totals.stream();
stream.count();
// stream.count();                      // IllegalStateException

totals.stream().filter(t -> t > 7);     // ничего не делает: нет терминальной операции

// int counter = 0;
// totals.forEach(t -> counter++);      // не компилируется: counter не effectively final
long counter = totals.stream().filter(t -> t > 7).count();   // правильный способ
